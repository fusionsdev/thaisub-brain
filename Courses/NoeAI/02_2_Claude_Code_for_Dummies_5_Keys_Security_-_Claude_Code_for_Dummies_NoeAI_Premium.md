ว่าไงครับทุกคน? ยินดีต้อนรับสู่อีกหนึ่งบทเรียนนะครับ วันนี้เราจะพูดถึง keys และ security ครับ อันนี้สำคัญมากจริง ๆ โดยเฉพาะถ้าคุณทำงานในบริษัทใหญ่ แต่ก็สำคัญกับทุกคนครับ เพราะเรากำลังพูดถึงว่า ถ้ามีคนได้ API keys หรือไฟล์ MCP ของคุณไป พวกเขาสามารถทำอะไรกับคุณก็ได้ ครับ เช่น ถ้าคุณมี Gmail พวกเขาสามารถเข้าไปใน Gmail ของคุณ แล้วเอาข้อมูลทั้งหมดของคุณไป พวกเขาสามารถขโมย หรือสร้างค่าใช้จ่าย API ที่มหาศาลก่อนที่คุณจะรู้ตัว เช่น หลายหมื่นดอลลาร์ ครับ มีคนที่อยากทำร้ายคุณอยู่จริง ๆ แม้คุณจะไม่รู้ตัว หรือคิดว่าไม่มีจริง ๆ ก็ตาม เชื่อผมเถอะ มีแฮกเกอร์ที่อยากใช้เงิน และพวกเขาจะใช้เงินของคุณเพื่อทำแบบนั้น พวกเขาสามารถแฮกเข้าไปขโมยไฟล์ .env ของคุณ หรืออะไรพวกนั้นได้ครับ

วันนี้ผมจะโชว์วิธีหลีกเลี่ยงเรื่องพวกนี้ และปลอดภัยสุด ๆ ต่อไปครับ ในบทเรียนที่แล้ว เราสร้าง MCP connection ของเราเอง ผมโชว์ keys ให้ดู ซึ่งก็ไม่ใช่สิ่งที่ปลอดภัยที่สุดที่ควรทำ และจริง ๆ ผมน่าจะลบมันทิ้งก่อนแล้ว แต่เราจะนำ MCP หรือ keys เหล่านั้น มาสร้างสิ่งที่เรียกว่า gitignore ครับ เมื่อจะ push ขึ้น GitHub ครับ ผมรู้ว่าฟังดูเยอะ เดี๋ยวผมจะอธิบายทีละอย่างก่อน แล้วค่อยเริ่มลงมือครับ

อย่างที่ผมเคยอธิบายในบทเรียนที่แล้ว MCP และ .env เก็บข้อมูลที่ละเอียดอ่อนมาก ครับ มันทำหน้าที่สองอย่างที่ต่างกัน .env คือที่ที่ keys ทั้งหมดของคุณอาศัยอยู่ครับ API keys ทั้งหมดของแอป URL ทั้งหมด ทุกอย่างที่เป็นความลับของแอปที่คุณเชื่อมต่อ จะอยู่ในไฟล์ .env นี้ครับ และถ้าคุณมี API keys กระจายอยู่หลายที่ ซึ่งผมก็เป็นแบบนั้น สมมติว่าผมมีหลาย keys และทุกอย่างกระจายกัน คุณต้องแน่ใจว่าคุณ rotate keys อยู่ตลอดเวลา ครับ

คุณจะสังเกตว่าผมมีไฟล์ .env เฉพาะสำหรับโปรเจกต์นี้ครับ เมื่อไหร่ก็ตามที่ผมเปิดโฟลเดอร์ school community ตัวอย่างนี้ สมมติว่ามันเป็นโฟลเดอร์ส่วนตัวของผม และผมมีการเชื่อมต่อในนี้ที่ต่างจากอีกโปรเจกต์หนึ่ง ผมจะเก็บไฟล์ .env แยกตามโปรเจกต์ครับ เพราะผมอยากให้ keys อยู่ในโฟลเดอร์นั้นโดยตรง ไม่อยากให้ธุรกิจอื่นของผมเข้าถึง keys เหล่านี้ได้ ผมอยากแยกทุกอย่างออกจากกันครับ นั่นคือเหตุผลที่ผมสร้างมันในโปรเจกต์ ถ้าผมทำแบบ global อย่างที่เราคุยกันไปแล้ว คุณก็สามารถใช้ keys เหล่านี้ข้ามหลายโฟลเดอร์ได้ทุกเมื่อ แต่คุณต้องแน่ใจว่าคุณรู้ว่ามันอยู่ที่ไหนทั้งหมด และต้อง rotate keys อยู่เสมอครับ

ถ้าคุณไม่รู้ว่า rotating keys คืออะไร มันก็คือการได้ key ใหม่สด ครับ หมายถึงเข้าไปในระบบของคุณ เช่น ผมเข้าไปที่ Airtable ที่เราสร้างไว้ ถ้าผมเปิดเจ้านี่ขึ้นมา โอเค มันจะเปิดขึ้นมา เห็นไหมว่าเราสร้างยังไง จริง ๆ ผมลบ key ที่เราใช้ทำงานไปแล้ว ถ้าคุณอยาก rotate keys เพราะคิดว่ามีคนรู้ key คุณก็แค่กด regenerate token ครับ regenerate token จะสร้าง token ใหม่ให้คุณ ผมแนะนำเสมอว่า ถ้าคุณทำงานในบริษัทใหญ่ ที่อาจมีการรั่วไหลเยอะ และคุณไม่แน่ใจเรื่องความปลอดภัย คุณควร rotate keys เดือนละครั้งครับ

อีกมาตรการที่ดีที่ควรมีคือ การจำกัดการใช้จ่ายของคุณเสมอ ตัวอย่างที่ดีคือ Google AI Studio ครับ ถ้าผมเปิด Google AI ขึ้นมา เข้าไปที่ Google แล้วอันนี้เป็นตัวอย่างที่ดีที่ทุกคนควรเห็น ถ้าผมเข้ามาตรงนี้แล้วไปที่ API ของผม ครับ ข้างในมี billing account ของผม โอเค ผมคลิกเข้าไปใน billing account แล้วตั้งค่าใช้งานว่าใช้จ่ายได้เท่าไหร่ ครับ อยู่ไหนนี่ ขอบคุณที่โชว์ว่าใช้ AMAX อะไร แต่คุณสามารถกลับไปได้ ใน billing บางอันมันให้คุณดูได้ แบบนี้ ผมดูค่าใช้จ่ายของผมได้ตรงนี้ ลองดู ถ้า 520 monthly cap ผมตั้ง spend cap ได้ ครับ ผมตั้ง cap ไว้ 10 ดอลลาร์ แล้ว key เฉพาะนี้จะใช้จ่ายได้แค่เท่านั้น ครับ ถ้ามีคนแฮกผมได้และเอา key ไปใช้ มันก็จะตัดที่ cap ครับ ผมก็ไม่ต้องกังวลอีกต่อไป

ถ้าผมไม่มี monthly spend cap หรือไม่มี spend cap เลย พวกเขาสามารถใช้จ่ายเป็นพันเป็นแสนดอลลาร์ได้ ครับ ผมเคยเห็นเรื่องสยองบน Reddit มีคนโดนแฮก แล้วมีคนรันค่าใช้จ่ายบน API key ของเขา และคุณเดาได้เลยว่าเกิดอะไรขึ้น มันเป็นความผิดของคุณ คุณไปที่บริษัทบัตรเครดิตแล้วบอกว่าผมขอ dispute มันไม่ทำงานแบบนั้นหรอก พวกเขาจะไม่เข้าข้างคุณ เพราะคุณขาดมาตรการรักษาความปลอดภัย ครับ ดังนั้นมันสำคัญที่คุณต้องตั้ง spend caps และเก็บ keys ของคุณอย่างปลอดภัยในไฟล์ .env และแน่ใจว่าไม่มีใครเข้าถึงมันได้ โอเค

แล้วไฟล์ MCP JSON ของคุณก็มี keys ด้วยครับ มันเหมือนมีข้อมูลซ้ำกันสองที่ อย่างที่ผมเคยอธิบายว่า Claude Code ทำงานยังไง ถ้ามันอยากเข้าถึงแอปหนึ่ง มันจะเข้าไปที่ไฟล์ .env แล้วดึง key ไปใช้ และบางครั้งคุณต้องมี key เดียวกันทั้งสองที่ เพราะ MCP ไม่ทำงานถ้าไม่มี key เขียนไว้ตรง ๆ ด้วยเหตุผลบางอย่าง ดังนั้นคุณต้องสลับเปลี่ยนไฟล์ .env และ keys อยู่เรื่อย ๆ ครับ ทุกครั้งที่คิดว่ามันรั่วไหลหรืออะไรก็ตาม และจริง ๆ แล้วพวกเขาจะส่งอีเมลหาเราด้วยนะครับ ถ้ามีข้อมูลรั่วไหลเกี่ยวกับ keys ของคุณ พวกเขาจะแจ้งให้คุณเข้าไป rotate keys อะไรแบบนั้น แต่สำคัญมากที่คุณต้องตั้งรับอยู่เสมอ และเปลี่ยนไฟล์ .env และ MCP ของคุณเป็นประจำ โอเค และอัปเดต rotate keys ของคุณครับ

สิ่งที่คุณไม่ควรทำเด็ดขาดคือ การวาง keys ลงใน CLAUDE.md ของคุณครับ ถ้าผมดู ดูว่า CLAUDE.md ตรงนี้ไหม เราไม่ควรใส่ keys ลงไปเด็ดขาด โอเค เพราะทุกครั้งที่ Claude Code เริ่มทำงาน มันจะอ่านไฟล์ทั้งหมดนี้ เมื่อมันมี .env มันก็ไม่ต้องอ่าน มันเป็นเหมือนไฟล์ซ่อน และก็เหมือนกันคือ อย่าโยน keys ของคุณลงในแชทโดยตรงครับ อย่าใส่ keys ลงในแชทโดยตรง เพราะมันจะบอกคุณว่า นี่คือ Claude Desktop ทางเทคนิค คุณจะไม่เข้าไปใน Claude Desktop แล้วพูดว่า นี่คือเลขบัญชีธนาคารและ routing number ของฉัน และนี่คือบัญชีของฉัน คุณจะไม่ทำแบบนั้นใช่ไหมครับ? มันก็เหมือนกันตรงนี้ คุณไม่ควรวาง API keys ของคุณ คุณต้องมอง tokens ของคุณเหมือนข้อมูลบัญชีธนาคาร ครับ

การวางไว้ในไฟล์ .env และ MCP ของคุณปลอดภัย มันอยู่ในเครื่องของคุณ ท้องถิ่น ไม่มีใครเข้าถึงได้ แต่ทันทีที่คุณวางมันลงในคอนเท็กซ์ มันจะอยู่บนเซิร์ฟเวอร์ของ Anthropic แล้ว ครับ และ Anthropic เคยถูกแฮกมาแล้ว ผมแค่อยากบอกไว้ตรงนี้ มันเป็นไปได้ที่ใครสักคนจะขโมยข้อมูลของคุณ ผมคิดว่าโอกาสน้อยมากไหม? ใช่ ผมคิดว่ามันโง่ไหมถ้าคุณทำแบบนั้น? ใช่ครับ

คุณรู้วิธีตั้งค่า .env และ MCP แล้ว และคุณสามารถถามเจ้านี่ได้เสมอ สมมติว่าผมอยากเชื่อมต่อกับ GoHighLevel ครับ คุณช่วยใส่ placeholder API key สำหรับ GoHighLevel GHL ในไฟล์ .env ให้หน่อยสิ อย่าใส่ key จริง แค่ใส่ dummy ไว้ก่อน โอเค แล้วมันก็จะฟังคุณ และใส่ลงในไฟล์ .env ครับ แล้วพอคุณอยากเชื่อมต่อกับแอป เห็นไหม ผมเปลี่ยนแล้วเสร็จ แล้วผมก็แค่ไปที่ไฟล์แล้ววางลงไป ผมไม่ต้องพิมพ์ว่า นี่คือ key ของฉัน แบบที่ผมเคยทำมานาน แล้วผมก็เพิ่งรู้ว่ามันโง่แค่ไหน เพราะมันง่ายมากที่คนอื่นจะเห็น โอเค มันอ่าน API key ของคุณไม่ได้ มันแค่ดึงค่าออกมาเป็น value แล้วเสียบเข้า MCP เท่านั้น และมันไม่เห็นค่าจริง ๆ มันไม่เก็บไว้ในความทรงจำของมัน นั่นคือวิธีการทำงาน อย่าโยน keys ของคุณลงในคอนเท็กซ์ของคุณเด็ดขาดครับ

สุดท้ายคือ ห้าม commit ไฟล์ .env หรือ MCP ขึ้น GitHub เด็ดขาดครับ อันนี้ใหญ่เลย เราคุยกันเรื่อง GitHub repo ไปแล้ว ถ้าผมไปที่ตัวอย่าง school ที่เรามี โอเค ถ้าเราสร้าง GitHub ขึ้นมา และถ้าคุณยังไม่ได้สร้าง ก็กลับไปดูบทเรียนก่อนได้ คุณควรทำมันแล้ว นี่คือที่ที่เราเก็บทุกอย่างเกี่ยวกับโฟลเดอร์ที่เราทำงาน ครับ เราสามารถ save commit และ push ได้ Commit คือการบันทึก และ push คือการอัปโหลดขึ้นคลาวด์ นี่คือคลาวด์ ครับ ดังนั้นคุณไม่ควร push ไฟล์ .env หรือ MCP JSON ของคุณขึ้นไปเด็ดขาด โดยเฉพาะถ้ามันมี keys อยู่ข้างใน โอเค เพราะมันอยู่บนคลาวด์ ซึ่งถูกแฮกได้

ผมจะโชว์สิ่งที่คุณควรทำจริง ๆ เพราะเราอยากเก็บไฟล์ .env และ MCP keys ไว้ในเครื่องของเรา เราไม่อยาก push มันขึ้น GitHub เราสามารถ push MCP server ขึ้นไปได้ครับ แต่เราไม่ต้องการ push มันพร้อมกับ key ตัวอย่างเช่น เพื่อนร่วมทีมของผมอยากตั้งค่า MCP server สำหรับ Airtable ของตัวเอง ผม push MCP server ขึ้น Airtable ได้ไหม โดยไม่ push key ไปด้วย แล้วเขาก็สามารถสร้าง key ของตัวเอง แล้วเก็บไว้ในเครื่องของเขาเอง แต่ผมไม่ push key เด็ดขาด ครับ

สิ่งที่เราจะทำคือแบบนี้ ดูนี่สิครับ เราจะสร้าง gitignore setup ครับ เปิดไว้ โอเค มันบอกว่าคุณสามารถเปิดไฟล์ gitignore และทำได้ แต่สิ่งที่เราจะทำคือแบบนี้ คุณช่วยสร้างไฟล์ gitignore ในโฟลเดอร์นี้หน่อยสิ แล้วเราจะใส่ API และ MCP keys ไว้ในนั้น เวลาที่เราจะ push ขึ้น GitHub มันจะไม่ push ไฟล์พวกนี้ไป ขอจัดระเบียบโฟลเดอร์ของผมด้วย โอเค เราสามารถขอให้มันตั้งค่าให้ได้ครับ และถ้าคุณไม่รู้ว่า gitignore คืออะไร gitignore คือไฟล์ที่บอก git ว่า เวลาที่เราจะ push มันจะรู้จักไฟล์ที่ต้องข้ามไป เห็นไหมครับ? API keys และ secrets สำหรับไฟล์ .env OS Python มันจะข้ามไฟล์พวกนี้ไป เมื่อเรา push ขึ้นไป มันจะไม่มีวันขึ้นไปถึง GitHub ซึ่งคือสิ่งที่เราต้องการ มันสำคัญมากครับ

เสร็จแล้ว ตอนนี้ gitignore ปกป้องไฟล์ .env และ MCP ของคุณแล้ว ไฟล์ Airtable ของคุณด้วย การ push ไฟล์ .env และ MCP JSON ของคุณจะไม่มีวันขึ้นไปบน GitHub ครับ มาทำ commit กัน ดูนี่สิ เรามีกี่โฟลเดอร์แล้ว โอเค ถ้าผมเปิดดู เรามีแค่ CLAUDE.md และอีกสองสามโฟลเดอร์ แต่เราจะ push ทั้งหมดนี้เข้าไป เพื่อให้ได้ภาพหน้าจอ ครับ แต่ดูนะ ไฟล์ MCP หรือ .env และ MCP JSON จะไม่ขึ้นไปอยู่ในนั้น โอเค ดูดี ไม่ ไม่ ไม่มี .env ความลับถูกแยกออก มันเป็นส่วนหนึ่งของโปรเจกต์ เยี่ยม ไม่รู้ว่าทำไมไม่มี readme ในนี้ ไม่อยากสร้างตรงนี้ แล้วดูเหมือนเราใกล้เสร็จแล้ว Pushed 45 ไฟล์ ไฟล์ .env และ MCP ของคุณยังคงอยู่ท้องถิ่น เยี่ยมครับ ถ้าผมรีเฟรช เห็นไหม ทุกอย่างถูก push ไปแล้ว เรามี snapshot ของมัน และคุณเห็นได้ว่ามัน commit เมื่อไหร่ คุณควรเห็น ถ้าคุณเข้าสู่ระบบวันนี้ แล้วก็ช่วยเพิ่ม readme ด้วย ขอโทษที่นอกเรื่อง แต่ผมอยากเห็น readme ด้วย มันอธิบายทุกอย่างที่อยู่ในโฟลเดอร์เหล่านี้ ครับ

เอาล่ะทุกคน นั่นคือทั้งหมดสำหรับความปลอดภัย ในการใช้ Claude Code และ GitHub ครับ มันสำคัญมากที่คุณต้อง rotate อย่างสม่ำเสมอ ตั้งมาตรการความปลอดภัยไว้ มีคนที่คุณไม่รู้จัก อยู่ไกลออกไป ที่อยากทำร้ายคุณ และคุณต้องตระหนักไว้ ไม่ใช่คิดว่าไม่มีอยู่จริง ในบทเรียนนี้ผมสอนวิธีทำอย่างละเอียดแล้ว ครับ ขอให้ทุกคนไปสร้างไฟล์ .env ของคุณ สร้าง MCP และสร้าง gitignore ด้วย Claude Code แล้ว push ขึ้น GitHub เหมือนที่เราทำทั้งบทเรียนนี้ เพื่อให้คุณมีทุกอย่างพร้อม และทุกอย่างปลอดภัย ไม่มีข้อมูลของคุณรั่วไหล เห็นไหมผมมี gitignore ที่กัน API keys ทั้งหมดออก และดูเหมือนว่ามี Airtable servers ที่เราตั้งค่าไว้ด้วย ครับ ไปจัดระเบียบของพวกนั้น ไปทำให้ทุกอย่างปลอดภัย แล้วเจอกันวิดีโอหน้าครับ บายครับ
