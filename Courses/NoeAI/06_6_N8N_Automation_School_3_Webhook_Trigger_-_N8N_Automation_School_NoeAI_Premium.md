## บทนำ

วิดีโอนี้สอนเรื่อง Webhook Trigger ใน n8n — ทริกเกอร์ที่ให้แอปภายนอก เช่น GoHighLevel เรียกเข้ามาเริ่ม workflow ได้ แถมสาธิตสดด้วยการให้ Claude Code ทดสอบ webhook ให้ดูแบบเรียลไทม์ พร้อมอธิบาย HTTP method และโหนด Respond to Webhook

## คำแปลเต็ม

ว่าไงครับทุกคน? ยินดีต้อนรับสู่วิดีโอทริกเกอร์อีกตอนครับ ในตอนนี้เราจะพูดถึง Webhook Trigger กัน อันนี้เจ๋งมาก วิธีอธิบายที่ง่ายที่สุด: webhook ก็คือทริกเกอร์ที่คุณเรียกใช้งานได้จากที่อื่น ที่ไม่ได้อยู่ใน n8n ครับ อย่างที่เห็น ถ้าเราจะเพิ่มทริกเกอร์อื่นๆ เช่นแบบ Manual (ทำเอง) หรือ On-Schedule (ตามกำหนดเวลา) หรือ Form (ฟอร์ม) หรือ Chat Message (ข้อความแชท) — พวกนี้ทั้งหมดอยู่ภายใน n8n ครับ

แต่สมมติว่าผมอยากให้ทริกเกอร์จากแอปอื่น เช่น อยากให้ทริกเกอร์จาก GoHighLevel — ถ้าผมมี automation ที่ทำงานอยู่ แล้วที่ท้ายสุดของมันมีแอ็กชันบอกว่า send webhook (ส่ง webhook) สิ่งที่มันจะทำก็คือมันจะมี URL มาหนึ่งตัว เรามี URL อยู่ตรงนี้ครับ มี HTTP method หลายแบบด้วยกัน เช่น PUT — ผมน่าจะอธิบายเรื่อง HTTP method ละเอียดๆ ในคอร์ส Claude Code อีกที แต่โดยสรุป HTTP ก็คือ คุณขอ GET ได้ ขอ DELETE ได้ ขอ PATCH ได้ HEAD ได้ POST ได้ ซึ่งก็คือการส่งข้อมูล หรือการอัปเดตอะไรแบบนั้น คุณไม่ต้องกังวลเรื่องนี้มาก เพราะ Claude Code จะจัดการพวกนี้ให้คุณเองครับ

โดยสรุปคือ มันมี URL หนึ่งตัว ยกตัวอย่าง GoHighLevel: ที่ท้ายสุดของ automation แอ็กชันถัดไปคือ call a post to this URL (ส่งคำขอ POST ไปที่ URL นี้) มันก็จะไปเรียก URL นั้น แล้วเมื่อมันเรียกแล้ว สิ่งที่จะเกิดขึ้นคือ มันจะส่งข้อมูลเข้ามาใน flow ของ n8n แล้วก็จะไปทริกเกอร์ workflow ครับ เดี๋ยวผมจะโชว์ให้ดูแบบสดๆ เราจะทำการส่ง POST แล้วใช้ Claude Code กันครับ

อีกเรื่องหนึ่งคือ คุณสามารถตั้งค่าให้ตอบกลับทันที หรือรอให้โหนดสุดท้ายตอบกลับได้ ผ่านโหนด Respond to Webhook ครับ เวลาส่ง webhook ออกไป ระบบจะตอบกลับไปยังต้นทางที่ส่งเข้ามา เพื่อบอกว่ามันสำเร็จหรือไม่สำเร็จ ตรงนี้คุณตั้งเป็น immediately (ตอบทันที) ได้ — พอโหนดไหนโหนดหนึ่งทำงานเสร็จ มันก็จะส่งกลับไปยังแหล่งข้อมูลได้เลยว่า ผ่านหรือไม่ผ่าน หรือจะตั้งเป็น when the last node finishes (เมื่อโหนดสุดท้ายเสร็จ) ก็ได้ ถ้าคุณมี workflow เต็มรูปแบบ แล้ว webhook เข้ามา ผ่าน flow ไปจนสุดทาง แต่สุดท้ายมันล้มเหลว มันก็จะส่งข้อความกลับไปยังต้นทางว่าอันนี้ไม่สำเร็จ ซึ่งก็ดีสำหรับการแจ้งเตือนครับ

การใช้โหนด Respond to Webhook: คุณวางไว้ท้ายสุดของ flow ได้ เช่น ถ้ามี webhook เข้ามา คุณก็แค่ดึงข้อมูลทั้งหมดมา ประมวลผล แล้วก็ตอบกลับไป มันจะตอบกลับทันที แล้วข้อมูลก็ถูกส่งกลับไป และมีเรื่อง streaming อีก — ผมเองก็ไม่รู้เหมือนกันว่ามันคืออะไร แต่เดี๋ยวผมจะโชว์ให้ดูว่ามันทำงานยังไงแบบเรียลไทม์กับ Claude Code จริงๆ ครับ

เราจะทำการ production (เผยแพร่) workflow แล้วผมจะคัดลอก URL นี้ แล้วก็เผยแพร่มัน แล้วคุณจะได้เห็น Claude ทำงานจริงๆ อันนี้ดีมากเลยครับ คุณจะได้ทดสอบ flow ต่างๆ ผ่าน Claude Code ได้ เดี๋ยวขอเปิดโปรเจกต์นี้ขึ้นมาก่อน อันนี้คือที่เราเคยทำงานด้วยกันเมื่อกี้ สงสัยว่าผมจะพิมพ์เองไปทำไมเนี่ย เพื่อความสะดวก: ช่วยส่ง webhook trigger ง่ายๆ ไปที่ URL นี้ให้หน่อย ผมจะได้เห็นมันทำงานแบบเรียลไทม์

โอเค มันอยู่ในสถานะ POST แล้ว — คุณต้องแน่ใจว่ามันเป็น POST ไม่งั้นมันจะไม่ทำงาน แล้วเราก็ส่งมันออกไป มันก็จะทริกเกอร์ทันที ครับ เวลาที่ Claude Code สร้าง workflow ให้ผม ผมจะใส่ webhook trigger ไว้เสมอ เพราะว่า Claude Code ไม่สามารถทริกเกอร์ flow ให้คุณได้ มันสร้างทั้ง workflow ได้ แต่ทริกเกอร์ไม่ได้ ด้วยเหตุผลแปลกๆ บางอย่าง แต่ถ้าคุณเพิ่ม webhook เข้าไป มันก็จะทำงานได้

เดี๋ยวผมจะโชว์ตัวอย่างจริงให้ดู: อย่าง workflow ดึงข้อมูล Instagram รายวันของผม ผมตั้งค่ามันไว้ถูกต้องแล้ว อันนี้จะดึงข้อมูล Instagram ทั้งหมดของผมทุกวันลงในฐานข้อมูล ซึ่งเดี๋ยวจะได้เห็นในคอร์ส Content System แต่เห็นไหมว่าผมใส่ webhook ไว้ตรงนี้? ตอนที่ผมสร้างมันด้วย Claude Code ผมก็ให้ webhook มา พร้อมบอกว่า นี่ URL ไปทดสอบไปเรื่อยๆ จนกว่าจะใช้ได้นะ อย่าให้ผมต้องกลับมาแก้บั๊กเอง ซึ่งช่วยได้เยอะมาก

มาดูกันว่าตอนนี้อยู่ตรงไหนแล้ว มันเหมือนกำลังสร้าง POST แล้วยังหาโหนด respond to webhook ไม่เจอใน flow เราลองดูว่ามันผ่านไหม โอ้ พระเจ้า บางทีอาจเป็นเพราะผมเปิดอะไรหลายอย่างพร้อมกันมากเกินไป ไปดูที่ executions แล้วก็... มันทำงานแล้ว! ดูเหมือนว่ามันส่งการแจ้งเตือนความล้มเหลวมาให้เรา มันบอกว่าไม่พบโหนด respond to webhook ใน workflow ของคุณ แต่ทริกเกอร์ยังทำงานอยู่ — คุณดู execution ได้ใน payload นั่นแหละ เห็นไหมว่ามันยิงทริกเกอร์จริงๆ แล้วผมก็แค่บอกว่า เราไม่จำเป็นต้องใช้โหนดนั้นแล้วนะ แล้วก็ republish (เผยแพร่ใหม่) บูม! ลองใหม่ ผมแก้แล้ว แล้วตอนนี้เราน่าจะเห็น execution ไหลเข้ามา... ผ่านไป 2 วินาที มันเข้า workflow แล้ว อยู่นั่นไง! มันทริกเกอร์ workflow ให้เราแล้วครับ

สรุปคือ webhook ช่วยให้คุณทริกเกอร์สิ่งต่างๆ จากแอปอื่น ที่ไม่ได้อยู่ใน n8n ได้ ซึ่งเจ๋งมากและจำเป็นมากสำหรับการพัฒนาของคนที่สร้าง AI automation และเจ้าของธุรกิจ นี่คือทั้งหมดของวิดีโอนี้ครับ แล้วเจอกันในบทเรียนถัดไป
