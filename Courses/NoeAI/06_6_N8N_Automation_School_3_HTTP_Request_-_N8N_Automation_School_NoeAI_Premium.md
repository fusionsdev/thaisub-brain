ว่าไงครับทุกคน? ยินดีต้อนรับสู่วิดีโอถัดไปนะครับ ในวิดีโอนี้ เราจะมาพูดถึง HTTP requests กันครับ อันนี้สำคัญมากเลยนะครับ ขออธิบายง่าย ๆ ว่า HTTP request คืออะไร HTTP request ก็คือโหนดพวกนี้แหละครับ เห็นโหนด Airtable นี่ไหมครับ อันนี้ก็เหมือน HTTP แต่เป็นแบบ native ในตัวอยู่แล้ว เมื่อผมบอกว่ามันติดตั้งมาให้แล้วภายในโหนดทุกตัว ครับ HTTP request แค่เปิดโอกาสให้คุณออกไปขอข้อมูลจากที่อื่นได้ครับ ผมจะโชว์ให้ดูในนี้ คุณมี client และ server ครับ คุณคือ client ส่วนผมคือคนที่เรียกขอข้อมูล

ตัวอย่างเช่น สมมติว่าคุณนั่งอยู่ที่ร้านอาหาร และอยากสั่งอาหาร ครับ คุณนั่งอยู่ที่โต๊ะ แล้วกำลังกินอะไรอยู่ก็ตาม โอเค พนักงานเสิร์ฟครับ พนักงานเสิร์ฟก็เหมือนตัวกลาง ส่วนห้องครัวอยู่ตรงนี้ เรามีพ่อครัวอยู่ข้างหลัง กำลังทำอาหารสด ๆ อยู่ โอเค พนักงานเสิร์ฟเดินมาหาคุณ แล้วถามว่า อยากกินอะไรครับ? ทักษะการวาดรูปผมแย่มาก แต่แบบนี้แหละ พนักงานเสิร์ฟถามว่า คุณอยากกินอะไร? แล้วคุณก็บอกว่า ผมอยากได้ขนมปัง ผมอยากได้ขนมปัง นั่นแหละคือการส่ง request หนึ่งครั้ง เพื่อขอขนมปังหนึ่งอัน ครับ คุณคือ client ที่ส่ง request แล้วพนักงานเสิร์ฟก็นำไปส่งต่อให้ห้องครัว ซึ่งก็คือ server ครับ server ก็คือแอปที่ให้บริการข้อมูลนั่นแหละ มันก็แค่นั้นเองครับ

ตัวอย่างเช่น GoHighLevel ถ้าผมอยากดึงรายชื่อผู้ติดต่อทั้งหมดของผม request ที่ผมส่งจากฝั่ง client คือการขอข้อมูลผู้ติดต่อ ครับ พนักงานเสิร์ฟก็ไปขอข้อมูลในระบบ แล้วก็ส่งข้อมูลกลับมา ง่ายมากใช่ไหมครับ เห็นใน Airtable ไหม ผมกำลังขอข้อมูล records ทั้งหมดในนั้น อันนี้ถูกสร้างไว้ล่วงหน้าแล้ว ส่วน front-end ที่ผู้ใช้เห็น ก็แค่ทำให้ HTTP request ดูสวยงามและเข้าใจง่าย แต่เบื้องหลังจริง ๆ แล้วมันคือ HTTP requests หลาย ๆ ครั้งนั่นแหละครับ ดังนั้นเวลาคุณขอข้อมูลจากที่ไหนสักแห่ง คุณกำลังทำ HTTP request โดยปริยายครับ

นี่คือสี่เมธอดหลักที่คุณต้องเข้าใจครับ เริ่มจาก GET ครับ GET คือ ผมอยากได้ข้อมูล ผมกำลังร้องขอข้อมูล อย่างที่ผมบอกในตัวอย่าง ถ้าผมกำลังขอขนมปัง นั่นคือ request ของผม GET คือผมต้องการมัน โอเค ส่วน POST นั้นต่างกันโดยสิ้นเชิงครับ POST คือ ผมกำลังส่ง records ผมกำลังส่งข้อมูล ผมส่งข้อมูลไปที่ไหนสักแห่ง ครับ ถ้าผมอยากส่งข้อมูลเข้า GoHighLevel ผมก็ POST ข้อมูลเข้าไป ครับ ต่างจาก GET ที่เป็นการดึงข้อมูลออกมา ส่วน POST คือการดันข้อมูลเข้าไป ครับ เหมือนกับว่าเรามีขนมปัง ผมเพิ่งทำขนมปังเสร็จ แล้วผมกำลังส่งมันไปที่ห้องครัว ผมส่งมันไปที่ห้องครัว พนักงานเสิร์ฟคงไม่ส่งแบบนั้นจริง ๆ หรอก แต่คุณคงเข้าใจที่ผมพูดนะครับ

ต่อมาคือ DELETE ครับ Delete คือการลบข้อมูล ผมส่ง request เพื่อลบบางอย่าง ตัวอย่าง GoHighLevel ถ้าผมอยากลบข้อมูล ผมก็ส่ง request ไปขอให้ลบข้อมูลนั้น ครับ ผมส่งไป มันก็ลบ แล้วตอบกลับมาว่าสำเร็จ แล้วก็มี PUT ครับ PUT คือการอัปเดตข้อมูล ถ้าผมอยากอัปเดต record หนึ่ง ผมก็ส่ง request ไปขอให้อัปเดต มันก็อัปเดต แล้วส่งกลับมา โอเค ตรงไปตรงมามากครับ ยังมีเมธอดอื่นอีกนิดหน่อย แต่สี่ตัวนี้คือตัวหลักที่คุณต้องรู้จริง ๆ ครับ ผมจะไม่ลงลึกมากในคอร์ส n8n นี้ คุณแค่ต้องรู้พื้นฐานทั้งหมดนี้ เพราะตอนที่คุณทำใน Claude Code คุณจะเข้าใจว่ามันทำงานเบื้องหลังยังไง โอเค

มาลองทำ HTTP request จริง ๆ กันครับ อันนี้มาจากบทเรียนที่แล้ว เอาของพวกนี้ออกไปก่อน HTTP request node นี่มันเป็นอะไรที่ดูไม่สวยที่สุดในโลกเลยครับ ถ้าผมเข้าไปใน HTTP เห็นไหมครับ มีหลายอย่างที่มากับ HTTP request คุณมี URL และ endpoint ครับ ถ้าคุณไม่รู้ว่ามันคืออะไร เดี๋ยวจะโชว์ให้ดูทันทีครับ ด้วย HTTP คุณสามารถค้นหาว่าธุรกิจมีอะไรให้ใช้ได้บ้าง โดยการดู API documentation ครับ สำหรับทุกแอปบนโลกนี้ ผมจะค้นหา API docs เสมอครับ ถ้าซอฟต์แวร์ตัวไหนไม่มี API ผมจะไม่ใช้มันเลยครับ ผมไม่ใช้เด็ดขาด เพราะผมอยากใช้ Claude Code ร่วมกับแอปของพวกเขา ถ้าไม่มี API ผมก็เชื่อมต่อแอปของพวกเขากับ Claude Code ไม่ได้ เชื่อมต่อกับระบบอัตโนมัติของผมซึ่งก็คือ n8n ไม่ได้ แล้วสุดท้ายผมก็ไม่ใช้มันเลยครับ ถ้าคุณกำลังดูอยู่และกำลังสร้างซอฟต์แวร์ ให้แน่ใจว่าคุณมี API docs เพราะคนแบบผมจะไม่ใช้มันถ้าไม่มี ครับ

API docs หน้าตาแบบนี้ครับ มันคือรายการยักษ์ ๆ ของสิ่งที่ทำได้ทั้งหมด แค่นั้นเองครับ สิ่งที่คุณต้องทำคือเข้าไปดู ครับ GHL คือ API docs ที่ดีที่สุดที่ผมเคยเห็นในชีวิตเลย พวกเขามี customization มากมายที่ทำผ่าน API ได้ ลองดูที่ contacts ครับ ใน GoHighLevel จาก Claude ผมสามารถดึงข้อมูลผู้ติดต่อ อัปเดต ลบ หรือ upsert ได้ครับ ถ้าคุณเห็นคำว่า Upsert มันหมายถึง insert หรือ update นั่นแหละ ผมสร้างหรืออัปเดต record ได้ ผมค้นหา contacts ตาม business ID ได้ ผมสร้างได้ ซึ่งคือ POST และผมดึงข้อมูล contacts ได้ ซึ่งคือการดึงหลายรายการ

เมื่อคุณเข้ามา สมมติว่าผมอยากดึงข้อมูลสักอัน ผมไม่ได้ใช้ GHL จริง ๆ นะ แต่คุณจะเห็นว่ามี curl ครับ curl คืออะไร? curl ก็คือ HTTP request ในบล็อกโค้ดเล็ก ๆ ครับ เราจะใช้ curl ทุกครั้ง ซึ่งเดี๋ยวผมจะลงรายละเอียดในบทเรียนต่อ ๆ ไป แต่ภายใน API ทั้งหมด คุณจะเห็นหลายสิ่ง ครับ คุณจะเห็น requirements ครับ กับ HTTP มันจะไม่สำเร็จถ้าคุณไม่ผ่านข้อกำหนดบางอย่าง และข้อกำหนดนั้นก็คือ scopes ครับ scope ใน GoHighLevel กับ API token ของคุณ คุณให้สิทธิ์มันไปแล้ว คุณให้ scopes กับมัน ครับ scope ก็คือสิทธิ์ เช่น อ่านผู้ติดต่อได้อย่างเดียว read-only สำหรับผู้ติดต่อ ผมให้ความสามารถนี้กับมัน ผมให้เครื่องมือนี้กับมันเพื่อให้มันทำได้ ดังนั้นมันต้องมี scope นี้ครับ จากนั้นก็มี OAuth access token หรือ private integration token นั่นคือวิธีที่คุณ authorize คำขอ API ครับ แล้วก็ token types ซึ่งก็คือวิธีที่ผมเข้าถึงข้อมูล นี่คือกฎที่ผมให้มัน หรือเครื่องมือที่ผมให้มันใช้เพื่อดึงข้อมูล แล้วก็มี token อีกแบบนึง ซึ่งผมไม่ค่อยได้ใช้ก็ไม่เป็นไรครับ

แล้วก็มี request headers และ parameters ครับ เวลาคุณทำ HTTP request คุณจะมี headers ครับ เช่น header สำหรับ authorization โดย authorization จะเป็นแบบ Bearer ตามด้วย API key ซึ่งยาวหลายตัวอักษร แล้วก็มีเวอร์ชันของ API ครับ ซึ่งก็คือวันที่ เช่น สำหรับ GoHighLevel มันคือ 2021-07-28 นั่นคือเวอร์ชันจริง ๆ แล้วคุณใส่ลงใน authorization header จากนั้นบางตัวก็มีอีกอันนึงที่เป็นแบบ JSON คือบอกว่ารับรูปแบบ code แบบไหน ซึ่งปกติคุณจะเห็นประมาณสามแบบ น่าสนใจดี หรือจะว่าก็ไม่น่าสนใจเท่าไหร่ แต่คุณเข้าใจที่ผมพูดนะครับ

แล้วก็ path parameters ครับ ใน HTTP request คุณจะเห็น query parameters, send headers, send body ครับ อย่างที่เราคุยกันไปแล้ว มันรับอะไรได้บ้าง? แล้วก็มี path ครับ path คือข้อมูลจริง ๆ เช่นข้อมูลที่เราอยากขอ และความแตกต่างระหว่าง query กับ header กับ body นั้นค่อนข้างสับสน แต่เราเลยใช้ curl ครับ curl ก็คือโค้ดหนึ่งบรรทัดที่มีข้อมูลทั้งหมดอยู่ มันมักจะเริ่มด้วย Bearer แล้วตามด้วย API token ของคุณ ครับ Contact ID ครับ มันดูประมาณนี้ นี่คือค่าที่ต้องกรอกเพื่อดึงข้อมูลผู้ติดต่อจริง ๆ ผมจะใส่เลขปลอม ๆ เข้าไป แล้วคุณก็แค่เลือก แบบนั้น แล้วคุณก็สามารถทดสอบ API request ได้ในนี้เลย ผมจะไม่ทดสอบให้เสียเวลา แต่แล้วคุณก็มี base URL ครับ นี่คือจุดเรียกหลัก แล้วคุณจะเห็นว่ามันเขียนว่า contact ID มันจะทำอะไร? มันจะนำ contact ID นี้ไปใส่ในนี้ เห็นไหมว่ามันเป็น get contact? นี่คือ endpoint ครับ base URL คือ services/leadConnector แล้วเราอยากได้ข้อมูลผู้ติดต่อ มันก็ต่อ contacts/ ตามด้วย ID เพื่อให้รู้ endpoint ที่ถูกต้อง โอเค มันจะไปที่ URL นี้ภายใต้ contacts สำหรับ contact ID นี้ แล้วใช้ API token และเวอร์ชันเพื่อปลดล็อกบัญชีของเรา แล้วดึงข้อมูลออกมา ครับ
