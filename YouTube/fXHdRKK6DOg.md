## ประเด็นหลัก

- Memory ในตัวของ Hermes โหลดจาก user.md และ memory.md ตอนเริ่มแชทเท่านั้น — บน Telegram แชทยาวควรใช้ /new เพื่อให้ learning loop ทำงาน
- เปิด tool visibility บน Telegram เพื่อเช็คว่า agent เซฟ memory จริงหรือแค่พูดว่าเซฟแล้ว โดยเฉพาะกับ local model เล็ก
- Honcho ให้ memory นอกแชท ใช้ข้าม Hermes Claude Code Codex Cursor ได้ และเรียนรู้แบบ real-time
- อย่าสลับ model กลางแชทยาว เพราะทำลาย provider cache (ส่วนลด ~75-90%) — ใช้ /new แล้วค่อย /model
- ย้ายงานข้าง (compression / vision / safety / background review) ไป model ถูก เช่น GPT-6 Luna บน ChatGPT subscription
- งาน ≥5 ขั้นที่ทำซ้ำ → เซฟเป็น skill; ใช้ /learn จากเว็บ โฟลเดอร์ หรือหนังสือทั้งเล่ม
- Scheduled jobs ต้องมี prompt ครบ ใช้ [Silent] เมื่อไม่มีเรื่องสำคัญ เปิด continuity และแยก model ของ job
- งานยาวใช้ /goal + judge + gate แทนการ babysit; ทีม Hermes เคยรัน helper ~1393 ตัวใน ~19 ชม.
- Sub-agents วางแผนด้วย model แพง ลงมือด้วย model ถูก; แยก profile ตามธุรกิจ/คอนเทนต์ ห้ามชี้สอง agent ไปโฟลเดอร์เดียวกัน
- ลด agent bloat ด้วย /status /context /context all /compress และโหลดเฉพาะ tools ที่ใช้

## ความเห็นสรุป

คลิปนี้เป็นคู่มือปฏิบัติการใช้ Hermes Agent แบบรันงานจริง ไม่ใช่แค่ chatbot ครับ.
เจ็ดข้อผิดพลาดครอบคลุม memory ต้นทุน model skill automation งานยาว ทีม agent และ context bloat ครบวงจร.
ถ้าทำตาม checklist ท้ายคลิป ผู้ใช้ทั่วไปจะดึงประสิทธิภาพจาก Hermes ได้มากกว่าคนส่วนใหญ่อย่างชัดเจนครับ.
