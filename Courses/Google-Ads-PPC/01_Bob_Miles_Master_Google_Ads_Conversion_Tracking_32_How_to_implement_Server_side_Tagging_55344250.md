## บทนำ

ในวิดีโอนี้ บ๊อบ ไมลส์ (Bob Miles) จะพาเราติดตั้ง server-side tagging แบบครบวงจร ครับ เริ่มตั้งแต่การสร้างคอนเทนเนอร์ Google Tag Manager (GTM) แบบฝั่งเซิร์ฟเวอร์ การโฮสต์บนแพลตฟอร์ม middleware อย่าง Stape.io การตั้งค่า DNS และสคริปต์ GTM แบบกำหนดเอง เพื่อเลี่ยง ad blocker ไปจนถึงการย้ายแท็ก Google Analytics 4 (GA4) และแท็ก Google Ads conversion tracking มาทำงานบนฝั่งเซิร์ฟเวอร์ เหมาะสำหรับผู้ที่ต้องการวัดผลคอนเวอร์ชัน ให้แม่นยำ และเป็นมิตรต่อความเป็นส่วนตัวมากขึ้น ครับ

## คำแปลเต็ม

ในวิดีโอนี้ ผมจะแสดงวิธีตั้งค่า คอนเทนเนอร์ Google Tag Manager แบบ server-side (ฝั่งเซิร์ฟเวอร์) และวิธีโฮสต์คอนเทนเนอร์นี้ ภายในโซลูชัน middleware อย่าง stape.io ครับ คุณจะใช้แพลตฟอร์มอะไรก็ได้ คุณสามารถใช้ middleware ของบริษัทอื่น อย่าง Teggers หรือแม้แต่อย่างอื่นก็ได้ คุณจะใช้คลาวด์แพลตฟอร์มของ Google เอง เพื่อโฮสต์คอนเทนเนอร์ฝั่งเซิร์ฟเวอร์ก็ได้เหมือนกัน แต่ผมชอบใช้ stape.io ครับ ดังนั้น ผมจะสาธิตให้ดู โดยใช้แพลตฟอร์มนี้เป็นตัวอย่าง

สิ่งแรกที่เราต้องทำ ก็คือการสร้าง คอนเทนเนอร์ Google Tag Manager แบบ server-side ครับ ซึ่งผมได้ตั้งค่าไว้แล้ว สำหรับเว็บ ppcmastery.com ของเราเอง เดี๋ยวผมจะให้ดูตัวอย่างบางส่วนในภายหลัง แต่ตอนนี้ ผมจะสร้างคอนเทนเนอร์ใหม่ เพื่อสาธิตวิธีทำให้มันใช้งานได้จริง สำหรับตัวคุณเอง ครับ เริ่มจากเข้าไปที่บัญชี Google Tag Manager ของคุณ แล้วสร้างคอนเทนเนอร์ ภายในบัญชีของคุณ นี่จะเป็นคอนเทนเนอร์ทดสอบ สำหรับ ppcmastery ครับ

ขั้นแรก คุณต้องเลือกใช้แบบ server (เซิร์ฟเวอร์) สำหรับการติดตั้งฝั่งเซิร์ฟเวอร์ หรือสำหรับเป้าหมายฝั่งเซิร์ฟเวอร์ แล้วจึงสร้างคอนเทนเนอร์ ครับ หลังจากนั้น คุณจะมีตัวเลือกหลักอยู่ 2 ทาง คือ คุณสามารถใช้ tagging server ที่จัดสรรให้อัตโนมัติ ซึ่งเชื่อมโยง และโฮสต์อยู่บนคลาวด์ของ Google เอง หรืออย่างที่ผมชอบ คือใช้บริษัทอื่น ในกรณีนี้คือ stape.io ดังนั้น เราจะเลือกแบบ manually provision tagging server (จัดสรร tagging server ด้วยตนเอง) ครับ วิธีนี้จะให้ Container Config ID มา ซึ่งเราจะต้องใช้ ID นี้ ภายในบัญชี stape.io ของคุณ ผมจะคัดลอก ID นี้ไว้ก่อนแล้วครับ

ต่อไป เรามาดูที่ stape.io กันครับ ผมสร้างบัญชีไว้แล้ว และมีคอนเทนเนอร์ Google Tag Manager แบบ server-side ทำงานอยู่แล้ว สำหรับเว็บของเรา ซึ่งก็คืออันนี้ ผมสร้างไว้ก่อนหน้านี้แล้ว แต่ผมจะสร้างคอนเทนเนอร์ใหม่ เพื่อสาธิตให้เห็นว่า มันทำงานอย่างไรจริง ๆ ครับ เริ่มจากสร้างคอนเทนเนอร์ก่อน เราต้องใส่ชื่อคอนเทนเนอร์ แล้ว Stape.io ก็จะถามหา Container Configuration ของคุณ ซึ่งก็คือ Container Config ID ที่ Google Tag Manager เพิ่งให้คุณมานั่นเองครับ เราจะคัดลอก และวาง ID นี้ ลงไปตรงนี้

จากนั้น เราจะเลือกตำแหน่งเซิร์ฟเวอร์ (server location) ครับ โดยเฉพาะอย่างยิ่ง ถ้าคุณกังวลเรื่องนโยบายความเป็นส่วนตัว เรามีเซิร์ฟเวอร์ในยุโรป เราอยากให้เซิร์ฟเวอร์อยู่ใกล้บ้านเราให้มากที่สุด ครับ เนื่องจากผมอยู่ยุโรป ผมจึงเลือกใช้เซิร์ฟเวอร์ยุโรปตะวันตก ที่ตั้งอยู่ในเบลเยียม ผมจะเลือกอันนี้ ครับ จากนั้น ผมจะกดสร้างคอนเทนเนอร์ มันจะพาคุณไปยังหน้าแผนบริการ ผมจะใช้แผนฟรี (free plan) เพราะนี่เป็นเพียงการสาธิตเท่านั้น ครับ

จากนั้น คุณจะเข้าสู่หน้าตั้งค่า (setup screen) ซึ่งจะแสดงข้อความ verifying (กำลังตรวจสอบ) อยู่ตรงนี้ นั่นหมายความว่า stape.io กำลังค้นหา คอนเทนเนอร์ Google Tag Manager แบบ server-side ใหม่ของคุณ ซึ่งก็คือ ID เฉพาะนี้ครับ และจากจุดนี้ เราก็เริ่มตั้งค่าอย่างอื่นได้แล้ว

การตั้งค่าที่สำคัญที่สุดตรงนี้ ก็คือ Tagging Server URL ของคุณเอง ครับ โดยปกติ stape.io จะใช้ URL ในซับโดเมนของตัวเอง ซึ่งเชื่อมโยงกับบัญชี stape.io หรือ Google Tag Manager แบบ server-side ของคุณ แต่เราสามารถเปลี่ยน Tagging Server URL นี้ ให้เป็นซับโดเมนของเราเองได้ ครับ ซึ่งมีประโยชน์มากมาย เพราะเมื่อใช้โดเมนของคุณเอง คุณจะสามารถเลี่ยง cookie blocker หรือ ad blocker ต่าง ๆ ที่คอยกันไม่ให้คอนเทนเนอร์ GTM ของคุณทำงานได้ ครับ

ad blocker พวกนี้ทำงานยังไง? พวกมันจะสแกนดูข้อความ หรือคุกกี้ที่เว็บไซต์ต้องการจะตั้ง แล้วมองหาคำบางคำครับ ถ้าคุณใช้ Google Tag Manager แบบมาตรฐาน URL ของ Google หรือ URL เฉพาะของ GTM จะถูกเจอในนั้น และ ad blocker ก็จะรู้ทันทีว่า นี่คือ Google Tag Manager พวกมันก็จะบล็อกทันทีครับ แต่ถ้าคุณใช้ URL ซับโดเมนแบบสุ่ม ad blocker เหล่านั้น จะไม่เห็น หรือไม่รู้ว่า คุณกำลังส่งคำขอประเภทไหน ซึ่งจะช่วยเลี่ยงบล็อกเกอร์ได้เยอะมาก ครับ

ต่อไป คุณต้องเพิ่มโดเมน และซับโดเมนของคุณ ครับ สมมติว่าเราจะใช้ gtm.ppcmastery.com ซึ่งผมทำไว้แล้ว สำหรับคอนเทนเนอร์อื่นของผม มันเลยขึ้นว่า มีอยู่แล้ว งั้นเราจะใช้ gtm2.ppcmastery.com แทนครับ สิ่งเดียวที่คุณต้องทำ ก็คือเข้าไปที่การตั้งค่า DNS ของคุณ คุณต้องเข้าถึงการตั้งค่า DNS ได้ เพื่อชี้ A record ไปยังซับโดเมนนี้ โดยใช้ IP address เฉพาะ ซึ่งทำได้ง่ายมากครับ เดี๋ยวผมให้ดูว่า ในแพลตฟอร์มของเราเป็นยังไง ซึ่งสามารถทำได้ในโฮสติ้งทั่วไป ถ้าคุณมีสิทธิ์เข้าถึง ถ้าไม่มี ก็ต้องติดต่อผู้ดูแลเว็บของคุณครับ

ตรงนี้คือการตั้งค่า DNS ของ ppcmastery.com ครับ อย่างที่เห็น เราสร้าง A record แบบง่าย ๆ สำหรับซับโดเมน gtm.ppcmastery.com ไว้ และ A record นี้ ชี้ไปที่ IP เฉพาะ ที่บัญชี stape.io ของคุณใช้ติดต่อสื่อสารครับ เดี๋ยวผมให้ดูคอนเทนเนอร์อีกอัน ที่ผมมีอยู่ ซึ่งก็คืออันนี้ ตรงนี้คุณจะเห็นซับโดเมน อุ๊ปส์ ตรงนี้คุณจะเห็นซับโดเมน gtm.ppcmastery.com ครับ และอันนี้พร้อมใช้งานแล้ว ตั้งค่าได้อย่างถูกต้องสมบูรณ์ และตรงนี้ขึ้นสถานะ running (กำลังทำงาน) นั่นหมายความว่า มันรู้แล้วว่าการตั้งค่าทั้งหมดถูกต้อง และคอนเทนเนอร์ GTM แบบ server-side ของผม กำลังถูกโฮสต์อย่างถูกต้องในตอนนี้ครับ

ถ้าคุณทำตามขั้นตอนทั้งหมดนี้เสร็จแล้ว คุณได้สร้างคอนเทนเนอร์ Google Tag Manager แบบ server-side ตั้งค่า config แล้ว และสร้างซับโดเมนแบบกำหนดเอง จนพร้อมใช้งานแล้ว ต่อไปคุณก็ไปที่หัวข้อ code (โค้ด) แล้วตั้งค่า สคริปต์ Google Tag Manager แบบกำหนดเอง (custom script) ได้เลยครับ ตรงนี้ คุณต้องใช้ซับโดเมนที่เพิ่งตั้งค่าไป ซึ่งในกรณีของเราคือ gtm.ppcmastery.com ครับ จากนั้น คุณต้องลิงก์ไปยัง Web GTM ID ของคุณ เพราะคุณยังต้องมีเว็บคอนเทนเนอร์ Google Tag Manager อยู่ ซึ่งก็คืออันนี้ และคอนเทนเนอร์นี้ จะเป็นตัวส่งคำขอ หรือส่งบางคำขอ ไปยังคอนเทนเนอร์ Google Tag Manager แบบ server-side ของคุณ คุณจึงต้องใช้ Web Container ID ตรงนี้ด้วย ครับ

จากนั้น คุณต้องระบุแพลตฟอร์มของคุณ ครับ ถ้าคุณใช้ Shopify หรือ WordPress คุณจะได้โค้ดผลลัพธ์ที่ต่างกันออกไป ส่วนผมเลือก other (อื่น ๆ) เพราะเราใช้แพลตฟอร์มอื่น ที่ไม่ใช่ Shopify ครับ ตอนนี้เราก็จะสามารถสร้าง Web GTM Code ได้ และเราก็จะได้โค้ดจาก custom loader (ตัวโหลดแบบกำหนดเอง) มา ซึ่งโค้ดนี้ เหมือนกับโค้ดที่คุณจะได้จาก Google ในขั้นตอนติดตั้งเว็บคอนเทนเนอร์เลยครับ

ลองไปดูที่เว็บคอนเทนเนอร์ของเรากัน ถ้าเราเข้าไปที่เมนู admin แล้วไปที่ขั้นตอนติดตั้ง Google Tag Manager เราจะเห็นสคริปต์เดียวกันนี้ แต่ในค่าเริ่มต้น คุณจะเห็น URL googletagmanager.com ครับ และเนื่องจากเรากำลังโฮสต์คอนเทนเนอร์ของเรา บนโดเมนของเราเอง เราจึงสามารถแก้ลิงก์นี้ได้ ซึ่งนี่คือสิ่งที่ Stape ทำใน custom loader ของพวกเขาครับ คุณจะเห็นว่า โดเมนของคุณเองถูกนำมาใช้ นั่นคือ gtm.ppcmastery.com พร้อมกับ path แบบสุ่ม ซึ่งเป็นการตั้งค่าที่เลี่ยง ad blocker ต่าง ๆ ได้ ทำให้เว็บคอนเทนเนอร์ของคุณ ถูกเรียกใช้งานในกรณีส่วนใหญ่ ครับ

ตอนนี้ คุณต้องเปลี่ยนสคริปต์เว็บคอนเทนเนอร์เดิมของคุณ เป็นสคริปต์เว็บแบบใหม่ ที่สร้างขึ้นตรงนี้ครับ ถ้าคุณมีคอนเทนเนอร์ Google Tag Manager บนเว็บติดตั้งไว้แล้ว คุณต้องเปลี่ยนออก เป็นสคริปต์แบบกำหนดเองตัวใหม่นี้ ถ้ายังไม่มี คุณต้องวางโค้ดนี้ ในส่วน head และวางโค้ดนี้ ต่อจากแท็กเปิด body ทันที ครับ ผมทำไว้แล้ว ในการตั้งค่าหลักของเว็บผม เราลองไปดูที่หน้า scripts ของเว็บผม ซึ่งเป็นการตั้งค่าภายในแพลตฟอร์มของเรา ตรงนี้คุณจะเห็นสคริปต์ส่วนหัว (header scripts) หลายรายการ และนี่คือจุดที่ผมแก้ไขเว็บคอนเทนเนอร์ Google Tag Manager ของผม และอย่างที่เห็น คุณจะเห็น URL เฉพาะ gtm.ppcmastery.com ที่เรากำลังใช้อยู่ตอนนี้ ครับ นี่คือการชี้ข้อมูลทั้งหมด ไปยังเซิร์ฟเวอร์ของเราเอง

นั่นคือการตั้งค่าหลักขั้นแรกครับ ถ้าคุณทำถูกต้อง และทำตามคำแนะนำทั้งหมดของ stape.io เรียบร้อยแล้ว คุณก็จะได้ระบบที่ตั้งค่า และทำงานได้อย่างสมบูรณ์ครับ
แต่ตอนนี้ คุณต้องแก้แท็ก Google Analytics 4 (GA4) ของคุณ และตั้งค่าแท็ก Google Ads conversion tracking (การติดตามคอนเวอร์ชัน) ด้วยครับ เดี๋ยวผมจะให้ดูว่า ผมตั้งค่าให้กับ ppcmastery.com ยังไง ผมจะจำกัดขอบเขตไว้แค่ Google Analytics 4 และ Google Ads เท่านั้น เพราะนี่คือคอร์สเฉพาะทาง Google Ads ครับ แต่คุณสามารถทำแบบเดียวกันนี้ สำหรับการติดตามคอนเวอร์ชันของ Meta Ads หรือแพลตฟอร์มอื่น ๆ ที่คุณอยากใช้ กับคอนเทนเนอร์ Google Tag Manager แบบ server-side ของคุณก็ได้ แต่ผมจะไม่พูดถึงในวิดีโอนี้ ขอจำกัดไว้แค่ Google Ads และ Google Analytics 4 ครับ

เริ่มจากไปที่เว็บคอนเทนเนอร์ Google Tag Manager ของเราก่อน ซึ่งก็คือคอนเทนเนอร์ Google Tag Manager เดิม ที่คุณใช้อยู่ก่อนจะตั้งค่า server-side tagging นั่นแหละครับ เราต้องการลบแท็ก Google Ads conversion tracking ออกไป เพราะเราจะใช้มัน ภายในคอนเทนเนอร์ฝั่งเซิร์ฟเวอร์แทน และเราต้องปรับแต่งแท็ก Google Analytics 4 บางส่วนด้วยครับ

ถ้าคุณเปิดแท็ก Google Analytics 4 ขึ้นมา คุณจะเห็นการตั้งค่าที่เขียนว่า send to server container (ส่งไปยังคอนเทนเนอร์ฝั่งเซิร์ฟเวอร์) ซึ่งโดยปกติแล้ว การตั้งค่านี้จะไม่ถูกใช้งานครับ แท็ก GA4 ของคุณจะทำงานภายในเว็บคอนเทนเนอร์ Google Tag Manager หรือภายในเบราว์เซอร์ของผู้ใช้ แต่ถ้าคุณเลือกตัวเลือกนี้ ข้อมูลของ Google Analytics 4 จะถูกส่งไปยังคอนเทนเนอร์ฝั่งเซิร์ฟเวอร์ และจากตรงนั้น คุณก็ส่งต่อไปยัง Google Analytics 4 ได้อีกทีหนึ่ง ครับ

ดังนั้น ให้ติ๊กช่องนี้ แล้วตรวจสอบให้แน่ใจว่า คุณใช้ Server Container URL ที่ตั้งค่าไว้ใน stape.io ซึ่ง URL นี้ ถูกใช้ในสคริปต์ของคอนเทนเนอร์ Google Tag Manager ของคุณด้วย ผมจะใส่ gtm.ppcmastery.com ครับ ตอนนี้ hit และข้อมูลทั้งหมดของผม จะถูกส่งไปยังคอนเทนเนอร์ฝั่งเซิร์ฟเวอร์เฉพาะนี้ และนั่นคือทั้งหมด ที่คุณต้องทำ เพื่อให้แน่ใจว่า ข้อมูลของคุณถูกส่งไปยังคอนเทนเนอร์ฝั่งเซิร์ฟเวอร์แล้วครับ

ต่อไป เรามาเปิดคอนเทนเนอร์ GTM หลัก หรือคอนเทนเนอร์ฝั่งเซิร์ฟเวอร์ ที่เราใช้อยู่ตอนนี้กัน ในคอนเทนเนอร์นี้ คุณจะเห็นสิ่งที่เรียกว่า Clients (ไคลเอนต์) ครับ และถ้าคุณสร้างคอนเทนเนอร์ Google Tag Manager แบบ server-side ใหม่ Google Tag Manager จะสร้าง GA4 client ให้คุณโดยอัตโนมัติ ซึ่ง client นี้ เป็นค่าเริ่มต้นแบบสุ่ม ที่ใช้สื่อสารกับจุดข้อมูลทั้งหมด ที่คุณส่งมาจากคอนเทนเนอร์ Google Tag Manager ฝั่งเว็บครับ คุณจึงไม่ต้องแก้ไข client ตัวนี้

ส่วนแท็กของคุณ คุณต้องสร้างแท็กขึ้นมา ครับ คุณควรสร้างแท็ก conversion linker (ตัวเชื่อมคอนเวอร์ชัน) แบบปกติ ภายในคอนเทนเนอร์ Google Tag Manager ฝั่งเซิร์ฟเวอร์ ซึ่งตั้งค่าง่าย ๆ ผ่านเมนู tags ได้เลย คุณจะเห็นแท็ก conversion linker แบบค่าเริ่มต้น ครับ ตรวจสอบให้แน่ใจว่า ให้แท็กนี้ทำงานบนทุกหน้า (all pages) เพื่อเพิ่มความแม่นยำ ให้กับแท็กติดตามของ Google ครับ

อย่างที่เห็น ประเภทแท็กภายในคอนเทนเนอร์ server-side tagging ในตอนนี้ มีค่อนข้างจำกัดมาก จำกัดอยู่ที่แท็ก conversion และ GA4 เป็นหลักครับ แต่ก็มีแท็กบางตัว ที่คุณสามารถนำเข้า จาก community template gallery (แกลเลอรีเทมเพลตจากชุมชน) ได้ ลองไปดูตรงนั้นกันครับ อย่างที่เห็น เรามีแท็ก Facebook Conversion API บ้าง มีแท็ก Google Ads offline conversion (คอนเวอร์ชันออฟไลน์) ด้วย และมี HubSpot ที่คุณสามารถใช้ เพื่อเรียกแท็กฝั่งเซิร์ฟเวอร์ของคุณได้ ครับ อย่าลืมลองดู community template gallery ด้วย แต่แท็กดั้งเดิม (native tags) ค่อนข้างจำกัด ในช่วงเวลานี้ครับ ตอนนี้ ผมใช้คอนเทนเนอร์ Google Tag Manager ฝั่งเซิร์ฟเวอร์ เพื่อเรียกแท็ก Google Ads conversion tracking และแท็ก GA4 เท่านั้นครับ

มาเริ่มกันที่การตั้งค่าพื้นฐานของแท็ก GA4 ของคุณกัน เปิดแท็กนี้ขึ้นมาครับ นี่ก็คือ ถ้าคุณไปที่เมนู tags แท็กประเภท Google Analytics: GA4 ที่คุณหาเจอได้ตรงนี้ ก็เลือกอันนี้เลยครับ จากนั้น คุณต้องกรอก Measurement ID ของคุณ ซึ่งก็คือ Measurement ID ของบัญชี GA4 ที่คุณสามารถหาได้จากเว็บคอนเทนเนอร์ของคุณ ด้วย เพราะคุณใช้ ID นี้อยู่แล้ว ตรวจสอบให้แน่ใจว่า ใช้ ID เดียวกับแท็ก GA4 ฝั่งเว็บของคุณ ครับ ผมตั้งเป็นค่าแบบ dynamic (ไดนามิก) เพื่อไม่ให้เกิดข้อผิดพลาด กับแท็กในอนาคต แต่คุณจะใช้ค่าคงที่ (constant) ตรงนี้ก็ได้ครับ

จากนั้น สิ่งที่คุณต้องทำ ก็คือ เลือกตัวแปร event name (ชื่ออีเวนต์) สำหรับตัวเลือก Event Name ครับ ซึ่งก็คือชื่ออีเวนต์ ที่จะส่งไปยัง Google และอีเวนต์เหล่านี้ จะถูกคัดลอกมาจากคอนเทนเนอร์ Google Tag Manager ฝั่งเว็บของคุณ ครับ ถ้าผมกลับไปที่คอนเทนเนอร์ Google Tag Manager ฝั่งเว็บ ซึ่งอยู่ตรงนี้ ผมได้ตั้งค่าแท็ก GA4 ไว้บ้าง เช่น อีเวนต์ begin_checkout (เริ่มชำระเงิน) อีเวนต์ newsletter (สมัครรับข่าวสาร) และอีเวนต์ purchase (ซื้อสินค้า) และอีเวนต์ purchase นี้ มีพารามิเตอร์เพิ่มเติมรวมอยู่ด้วย มันจะส่ง item ID และข้อมูลทั้งหมด ที่เกี่ยวข้องกับการสั่งซื้อของผมไปด้วย ซึ่งทั้งหมดนี้ เป็นไปตามเอกสารทางการของ GA4 ครับ

ดังนั้น อย่าลืมตั้งค่าอีเวนต์ GA4 ของคุณให้ถูกต้อง แหล่งข้อมูลทางการ จะอธิบายวิธีตั้งค่าเหล่านี้ ให้คุณครับ เพราะพารามิเตอร์อีเวนต์ และค่าอีเวนต์ทั้งหมดนี้ จะถูกนำไปใช้ภายในแท็กฝั่งเซิร์ฟเวอร์ด้วย และเดี๋ยวผมจะให้ดูตัวอย่าง ในภายหลังครับ อีเวนต์เหล่านี้ จะถูกเรียกใช้งานภายในเว็บคอนเทนเนอร์ของผม ก่อน แล้วจึงถูกส่งไปยังการตั้งค่าหลักของผม ซึ่งก็คือแท็ก GA4 หลักอันนี้ ครับ เนื่องจากแท็ก GA4 นี้ ส่ง hit ทั้งหมดไปยังเซิร์ฟเวอร์ของผม ข้อมูลอีเวนต์ทั้งหมด ก็จะถูกส่งตามไปด้วย ดังนั้น อีเวนต์ของคุณ จะถูกตั้งค่า ในคอนเทนเนอร์ Google Tag Manager ฝั่งเว็บนั่นเอง ครับ

กลับไปที่คอนเทนเนอร์ฝั่งเซิร์ฟเวอร์ แล้วไปที่เมนู tags เปิดแท็ก GA4 ของผมอีกครั้ง คุณจะเห็นตัวเลือก event ครับ และเนื่องจากคุณส่งอีเวนต์ทั้งหมดมาจากฝั่งเว็บ แท็ก GA4 ฝั่งเซิร์ฟเวอร์ จะส่งชื่ออีเวนต์ทั้งหมดที่เข้ามา ไปยัง property ของ Google Analytics 4 โดยอัตโนมัติครับ

สำหรับการเรียกใช้งานแท็กของผม (trigger) จะใช้เงื่อนไขที่ว่า client name (ชื่อไคลเอนต์) เท่ากับ GA4 ครับ นี่คือ trigger แบบกำหนดเอง (custom trigger) เพราะเรามี trigger ไม่เยอะ แค่ 3 แบบเท่านั้น คุณควรใช้ custom trigger แล้วตั้งค่าให้เท่ากับชื่อไคลเอนต์ของคุณ ซึ่งคุณหาได้จากตรงนี้ ถ้าไปที่เมนู clients ครับ เนื่องจากชื่อของไคลเอนต์คือ GA4 แท็กของผมจึงทำงาน ทุกครั้งที่ไคลเอนต์นี้ได้รับการเรียก ทุกครั้งที่แท็ก GA4 ของผมทำงาน และไคลเอนต์นี้ได้รับการเรียก แท็กของผมก็จะถูกเรียกตามครับ

ประมาณนี้ สำหรับการตั้งค่า server-side tagging ของ GA4 ครับ และตรงนี้ ผมยังไม่ได้รวมเรื่องขั้นสูง อย่างการตั้งค่า consent mode (โหมดยินยอม) หรือการตั้งค่าที่เป็นมิตรต่อความเป็นส่วนตัวอื่น ๆ ซึ่งผมได้ตั้งค่าไว้แล้ว ในเว็บคอนเทนเนอร์ของผม อย่างที่เห็น ผมใช้ Cookiebot เป็นระบบจัดการคุกกี้ (CMP) และใช้ระบบ consent ในตัว เพื่อเรียกแท็ก GA4 อย่างเหมาะสม แต่ผมไม่อยากลงรายละเอียดมากเกินไป ในวิดีโอนี้ นี่เป็นแค่การตั้งค่าพื้นฐาน ที่ผมอยากพูดถึงเท่านั้นครับ

ต่อไป เรามาดูแท็ก Google Ads conversion ซึ่งสำคัญมากจริง ๆ ครับ ลองมาดูว่า ผมตั้งค่าอะไรไว้บ้าง ในคอนเทนเนอร์ Google Tag Manager ฝั่งเซิร์ฟเวอร์ ที่มีอยู่แล้วของผม คุณจะเห็นแท็ก conversion tracking ที่มีหน้าตาคล้ายกัน ซึ่งโดยพื้นฐานแล้ว เหมือนกับที่คุณเห็น ในเว็บคอนเทนเนอร์ของคุณ ครับ นี่คือจุดที่คุณใส่ Conversion ID และ Conversion Label ของคุณ และคุณยังสามารถระบุรายละเอียดอื่น ๆ และฟีเจอร์ขั้นสูงบางอย่างได้ เช่น ข้อมูลระดับสินค้า (product level) ลูกค้าใหม่ (new customer) ข้อมูลที่ผู้ใช้ให้มา (user-provided data) เพื่อใช้ประโยชน์จาก enhanced conversions (คอนเวอร์ชันที่เพิ่มประสิทธิภาพ) ได้ครับ ซึ่งหน้าตาจะเหมือนกัน

สิ่งที่ต่างกันจริง ๆ ตรงนี้ ก็คือ การตั้งค่า Conversion Value (มูลค่าคอนเวอร์ชัน) Conversion Currency (สกุลเงินคอนเวอร์ชัน) และ trigger ครับ เริ่มจาก trigger ก่อน ผมตั้ง trigger สำหรับแท็กนี้ ให้ทำงานเมื่อ client name เท่ากับ GA4 ดังนั้น ทุกครั้งที่ GA4 client ทำงาน trigger นี้ก็จะทำงานตาม แต่ผมได้สร้าง trigger ตัวที่สองขึ้นมาด้วย ซึ่งเรียกว่า event name (ชื่ออีเวนต์) ครับ
แท็ก purchase นี้ ต้องทำงานเฉพาะบนอีเวนต์ purchase เท่านั้น เพราะผมกำลังติดตามคอนเวอร์ชันแบบ purchase อยู่ตรงนี้ครับ ดังนั้น มันต้องมีเงื่อนไขว่า client name เท่ากับ GA4 และ event name เท่ากับ purchase ซึ่งเป็นอีเวนต์ที่ส่งมาจากเว็บคอนเทนเนอร์ ไปยังคอนเทนเนอร์ฝั่งเซิร์ฟเวอร์ ครับ

ทำไมผมถึงใช้เงื่อนไข client name เท่ากับ GA4? เพราะแท็ก Google Ads conversion tracking ประเภทต่าง ๆ นั้น โดยพื้นฐานแล้ว สร้างขึ้นบนโครงสร้างของ Google Analytics 4 ครับ

ถ้าผมไปที่ช่อง Conversion Value และ Currency แล้วดูที่เครื่องหมายคำถาม (ไอคอนช่วยเหลือ) Google จะอธิบายว่า นี่คือมูลค่าของคอนเวอร์ชัน ที่คุณต้องการส่งไปครับ ถ้าปล่อยช่องนี้ว่างไว้ มูลค่าของอีเวนต์จะถูกส่งแทน ดูเอกสารประกอบเพิ่มเติมได้ครับ ถ้าไปที่เอกสารทางการ Google จะบอกว่า Google ดูข้อมูลภายในอีเวนต์ GA4 ของคุณ เพื่อนำไปเติมลงในแท็ก Google Ads conversion ของคุณ ครับ

ตอนแรกตอนที่ผมตั้งค่านี้ ผมสงสัยว่า ทำไมผมถึงสร้างตัวแปร data layer (เลเยอร์ข้อมูล) ไม่ได้ เพราะตัวแปรที่คุณเลือกได้ ในคอนเทนเนอร์ฝั่งเซิร์ฟเวอร์ มีค่อนข้างจำกัด ถ้าไปที่เมนู variables คุณจะไม่เห็นตัวแปรอย่าง data layer variables หรืออะไรทำนองนั้น ผมเลยสงสัยว่า แล้วผมจะตั้งค่าตัวแปร conversion value ยังไง หลังจากลองไปลองมา ผมก็พบว่า Google จะดูข้อมูลภายในอีเวนต์ที่ส่งเข้ามา ซึ่งก็คืออีเวนต์ purchase ครับ และเนื่องจากผมส่งค่าตรงนี้ ภายใน GA4 ฝั่งเว็บอยู่แล้ว เรามาดูเว็บคอนเทนเนอร์ของผมอีกครั้ง ซึ่งก็คืออีเวนต์ purchase นี่ คุณจะเห็นว่า ผมส่งพารามิเตอร์อีเวนต์ตัวหนึ่ง ซึ่งมีชื่อเดียวกันกับในเอกสารทางการ ครับ

และแท็ก Google Ads conversion ภายในคอนเทนเนอร์ Google Tag Manager ฝั่งเซิร์ฟเวอร์ของคุณ จะค้นหาค่านี้ แล้วนำไปใช้ แม้ว่าคุณจะปล่อยช่องนั้นว่างไว้ก็ตาม ครับ ถึงแม้ผมจะปล่อยช่องนี้ว่าง ผมก็ยังส่งมูลค่าคอนเวอร์ชันจริง และรหัสสกุลเงินอยู่ดี แต่คุณจำเป็นต้องมีการติดตั้ง GA4 ที่ถูกต้อง เพื่อให้สิ่งนี้เกิดขึ้นได้ ซึ่งสำคัญมากครับ

นอกจากนี้ เรายังมีการตั้งค่า remarketing pixel (พิกเซลรีมาร์เก็ตติ้ง) ด้วย คุณสามารถใช้ remarketing pixel แบบพื้นฐาน ที่จะทำงานตามการเรียกของ GA4 client ก็ได้ครับ ซึ่งผมยังต้องหาวิธีตั้งค่า ให้เป็นไปตามกฎ GDPR/AVG อยู่ ตอนนี้กำลังศึกษาอยู่ครับ ตอนนี้มันทำงาน ทุกครั้งที่ GA4 client ถูกเรียก แต่จริง ๆ แล้ว ผมอยากให้มันทำงาน เฉพาะเมื่อได้รับความยินยอม ad_storage จากระบบจัดการความยินยอมของผม ซึ่งก็คือ Cookiebot เท่านั้นครับ

โดยสรุปแล้ว มันค่อนข้างซับซ้อน ถ้าคุณไม่เคยทำงานกับระบบนี้มาก่อน แต่สิ่งสำคัญที่ต้องรู้ ก็คือ โดยพื้นฐานแล้ว คุณยังคงใช้คอนเทนเนอร์ Google Tag Manager ฝั่งเว็บของคุณ สำหรับงานส่วนใหญ่ ครับ แต่คุณจะปรับแต่งสคริปต์ของคอนเทนเนอร์ของคุณบ้าง เพื่อให้เว็บคอนเทนเนอร์ Google Tag Manager ถูกเรียกใช้งานบ่อยขึ้น ครับ

คุณยังใช้คอนเทนเนอร์ฝั่งเว็บนี้ สำหรับการตั้งค่าแท็กหลัก และแท็กทั้งหมดที่ไม่เกี่ยวกับ Google ในกรณีส่วนใหญ่ครับ จากนั้น คุณก็ตั้งค่าเล็ก ๆ น้อย ๆ สำหรับผลิตภัณฑ์เฉพาะของ Google อย่าง GA4 พิกเซลคอนเวอร์ชันของ Google Ads และอื่น ๆ และคุณต้องการใช้แท็กประเภทเหล่านั้น ภายในคอนเทนเนอร์ฝั่งเซิร์ฟเวอร์ของคุณ เพื่อใช้ศักยภาพเต็มรูปแบบของ server-side tagging ครับ

ถ้าคุณอยากเจาะลึก เรื่องการตั้งค่าต่าง ๆ ที่คุณสามารถใช้และเลือกได้ ภายใน Google Tag Manager ฝั่งเซิร์ฟเวอร์ และวิธีการทำงานในรายละเอียด อย่าลืมไปดูบล็อกของ stape.io นะครับ พวกเขามีบล็อกที่ยอดเยี่ยม และมีบทความช่วยเหลือที่ยอดเยี่ยมด้วย ถ้าคุณกำลังติดตั้งระบบ ขอให้ทำตามขั้นตอนทั้งหมด ที่พวกเขาระบุไว้ เพื่อให้คุณตั้งค่าได้อย่างถูกต้อง ครับ

และเมื่อตั้งค่าทุกอย่างเสร็จแล้ว คุณจะเห็นป้ายสถานะ running (กำลังทำงาน) และป้าย ready (พร้อมใช้งาน) ที่ Tagging Server URL ของคุณ หลังจากที่คุณแก้ไขการตั้งค่า DNS แล้ว ครับ ถ้าคุณแก้ DNS แล้ว อย่าลืมรอสักสองสามชั่วโมง เพราะมันจะไม่ทำงานทันที ภายใน 5 นาที คุณต้องให้เวลา stape.io รับรู้การเปลี่ยนแปลงนี้ครับ

หลังจากตั้งค่าเสร็จ ถ้ามีข้อสงสัยอะไร ก็ไปดูบล็อกของ stape.io ก่อน หรือดูจากแพลตฟอร์มอื่น ที่คุณใช้อยู่ครับ และถ้าคุณมีคำถามเพิ่มเติม ทักมาหาผมได้เลย ผมยินดีช่วยเหลือครับ แล้วเจอกันครับ
