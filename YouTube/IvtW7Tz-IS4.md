## ประเด็นหลัก
- คนส่วนใหญ่ทำผิดพลาดด้วยการสร้างระบบ AI agent เยอะเกินไป ซึ่งทำให้ agent อ่อนแอลง แทนที่จะแข็งแกร่งขึ้น
- วิธีแก้คือใช้เซ็ตอัปที่เรียบง่าย: ระบบเดียวที่สะอาด เร็วขึ้น ฉลาดขึ้น และจัดการง่ายขึ้น
- ตอบคำถามของ Larry: ไม่ต้องลบไฟล์ความจำ (memory files) ของ Claude Code ทิ้ง — Agent OS ต่อยอดจากระบบความจำเดิมที่คุณมีอยู่แล้วได้ทั้งหมด
- การลบความจำช่วยได้แค่เรื่องลดจำนวน token แต่ไม่ใช่ข้อจำกัดของคนส่วนใหญ่ในตอนนี้
- ตอบคำถามของ Meron: ไม่แนะนำให้มี agent operating system สองระบบแยกกัน (dev กับ product) ควรใช้ระบบเดียวที่เรียบง่าย แม้มีหลายลูกค้าหรือหลายโปรเจกต์
- วิธีให้ agent คุยกันใน Telegram: แค่สร้าง group chat แล้วเพิ่ม agent ทั้งหมดเข้าไป พวกมันก็สื่อสารกันเองได้
- การสร้าง agent ของ Claude Code ฟรีจาก Hermes orchestrator: ใช้ Paperclip ได้ แต่ส่วนใหญ่ไม่จำเป็น — มักจะใช้แค่ Hermes agent ตัวเดียวก็พอ
- ถ้าอยากให้ agent หลายตัวทำงานเป็นทีมจริง ๆ ให้ตั้งค่า Paperclip พร้อม organization chart
- Hermes mixture of agents = กลุ่ม agent หลายตัวทำงานร่วมกัน มี aggregator รวมคำตอบให้ดีกว่าโมเดลเดี่ยว (สองหัวดีกว่าหัวเดียว)
- อาการ terminal time out เกิดจาก agent turn cap คือ agent หมดเวลาขณะหาคำตอบ
- สำหรับการดึงข้อมูลด้วย AI แนะนำ Appify ซึ่งมีตัวอย่างเวิร์กโฟลว์ให้ใช้งาน
- คอมมูนิตี้มีสิทธิประโยชน์ครบ: ตอบคำถามรายวัน, วิดีโอสอน, คอร์ส beginner to expert, คอลโค้ชชิ่งรายสัปดาห์ และแผนที่สมาชิกในพื้นที่

## ความเห็นสรุป
วิดีโอนี้ให้บทเรียนที่ตรงไปตรงมาและมีประโยชน์: ความเรียบง่ายชนะความซับซ้อนในการตั้งค่า AI agent และระบบ Agent OS ของ Julian ออกแบบมาให้รองรับระบบความจำและ agent เดิมที่ผู้ใช้มีอยู่แล้วโดยไม่ต้องเริ่มจากศูนย์ เหมาะสำหรับทั้งมือใหม่ที่เพิ่งเริ่มและคนที่กำลังจัดระบบ agent ของตัวเองให้เป็นระเบียบ
