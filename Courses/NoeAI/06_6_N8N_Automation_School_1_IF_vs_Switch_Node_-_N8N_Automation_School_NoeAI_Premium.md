## คำแปลเต็ม

ว่าไงครับทุกคน? ยินดีต้อนรับสู่อีกหนึ่งวิดีโอครับ ในวิดีโอนี้เราจะพูดถึง if node และ switch node ซึ่งสำคัญมาก ถ้าคุณทำงานเกี่ยวกับเงื่อนไข (conditional) เราจะลบข้อมูลทั้งหมดที่เราเพิ่งพูดถึงไปก่อน ถ้ายังไม่ได้ดูบทเรียนเรื่อง data ไปดูได้เลยครับ

โอเค มาที่ if node และ switch node กัน มันคือโฟลว์ คุณมีทุกอย่างแล้วที่เราเรียนไป แต่ if และ switch นั้น if โดยพื้นฐานคือ มันให้คุณจัดเส้นทางข้อมูลตามเงื่อนไขบางอย่าง ผมจะอธิบายให้ฟัง บางครั้งผมก็ลืมเหมือนกันว่ามันต่างกันยังไง แต่เดี๋ยวผมจะแยกให้ดูในวิดีโอนี้ครับ

ด้วย if node มันคือ true หรือ false โดยพื้นฐาน มันคือ conditional branch (เงื่อนไขแยกทาง) ถ้าข้อมูลตรงตามเงื่อนไขที่กำหนด คุณก็ส่งมันไปอีกทิศทางหนึ่ง ตัวอย่างเช่น สมมติเราเชื่อมต่อกับ Airtable และสมมติว่าเรามีค่า view count เราจะเอา view count มาดู views สมมติว่า ถ้าค่ามากกว่า แบบว่ามากกว่าหนึ่งแสน เพราะตอนนี้คุณมียอดวิวเยอะมากจริง ๆ สิ่งที่มันจะทำคือ ถ้ามันมากกว่าหนึ่งแสน เงื่อนไขเป็นจริง แล้วมันจะส่งข้อมูลไปตาม true branch ดูนะครับ

ปัง! มันควรจะส่งแค่ห้ารายการลงไปตรงนั้น ใช่แล้วครับ เราดึงเนื้อหามา 100 ชิ้น ผมโพสต์ไปจริง ๆ 500 ชิ้น แต่เห็นไหมว่ามันคือ true branch มันส่งทุกกิ่งที่เงื่อนไขเป็นจริงไป ลองดูครับ ดูที่ views ทั้งหมดนี้มียอดวิวเกิน แล้วมันส่งทั้งหมดลงไปที่ true branch ส่วนอันที่ต่ำกว่าเกณฑ์ก็ถูกส่งลง false branch

เห็นไหมครับว่าคุณใช้มันจัดเส้นทางข้อมูลตามสิ่งที่คุณกำลังมองหาได้ อีกตัวอย่างหนึ่งที่ผมใช้ if node คือ ถ้าผมอยากได้ทวีตที่มียอดเกินเกณฑ์ ผมจะใช้ if node เพื่อส่งให้ผม แต่นั่นก็แค่ if node มันคือเงื่อนไขล้วน ๆ ถ้าได้รับค่าตามเงื่อนไข มันก็ทำงาน

คุณทำเงื่อนไขหลายอันได้ด้วย เช่น สมมติ views มากกว่าห้า ซึ่งจะครอบคลุมทั้งหมด มันจะส่งประมาณห้ารายการลงไป แต่คุณใช้ or ได้ด้วย เช่น มากกว่าหนึ่งแสน หรือวิดีโอที่มีหนึ่งพัน ลองดูว่ามันเปลี่ยนข้อมูลยังไง บางรายการที่ view count ต่ำกว่า แต่มีจำนวนอย่างอื่นมากกว่า ซึ่งเจ๋งดี คุณจะเห็นว่าตอนนี้มีเก้ารายการ มันคือเงื่อนไขแบบ and/or นั่นเอง แล้วก็มี ignore cases อะไรแบบนั้นด้วย

ส่วน switch node ต่างออกไปเล็กน้อย อันนี้จะซับซ้อนขึ้นนิดหน่อย ถ้า if node คือ true หรือ false ถ้าตรงเงื่อนไขก็ส่งลงกิ่งเดียว ถ้าไม่ตรงก็อีกกิ่ง แต่ switch คุณมี routing rules (กฎการจัดเส้นทาง) แทนที่จะเป็น true หรือ false คุณมีค่าที่ตั้งไว้ ตัวอย่างเช่น ถ้าผมอยากให้ค่าของชื่อเป็น John, Rachel และ Sarah ทุกรายการที่เข้ามา ชื่อ John ก็จะส่งลงเส้นทาง John ส่วนที่ชื่ออื่นก็ส่งไปเส้นทางอื่น คุณกำลังจัดเส้นทางสิ่งต่าง ๆ นั่นเอง

ลองดูตรงนี้ เราทำ views ได้ แล้วก็ views is equal to แต่เราไม่อยากใช้ equal ลองใช้ is greater than ดู นี่คือตัวอย่างที่ดี เราจะส่ง views ที่มากกว่าหนึ่งแสนลงเส้นทางนี้ เราจะส่งลงเส้นทางนี้ แล้วก็ทำ views ที่อยู่ระหว่างค่า พอผมจะทำ range ดู มันทำไม่ได้เหรอ? เราไม่สามารถทำช่วงระหว่างค่าได้ แปลกจริง ๆ มันมี is not equal to, is greater than, is less than, is greater or equal, is less or equal, contains โอเค เจ๋ง เราทำ is less than เก้าหมื่น หรือหนึ่งแสนได้ และนั่นคือกรณีการใช้งานที่สมบูรณ์แบบตรงนั้นเลย

เราสร้าง true/false ของเราเองได้โดยพื้นฐาน แต่เหมือนคุณจะได้ if ที่ปรับแต่งได้มากกว่า แต่ก็ไม่ได้มีหลายสถานการณ์ที่ผมใช้ switch node มากกว่า if node ผมจะใช้ switch node เมื่อมีหลายสตรีมที่ต้องส่งข้อมูลลงไป เช่น ถ้าผมเพิ่มหลายช่องทาง แล้วตอนนี้มีหลายสตรีม ผมใช้มันเพื่อการจัดหมวดหมู่ชื่อเป็นหลัก ถ้าข้อมูลเข้ามาเป็นชื่อใดชื่อหนึ่ง ตัวอย่างเช่น ถ้าผมกำลังสแครปข้อมูลจากโซเชียลทั้งหมด หรือมี records ทั้งหมดจากทุกแพลตฟอร์ม และข้อมูลทั้งหมดมาเป็นพัน records ผมเปลี่ยนอันนี้เป็น Twitter และ TikTok แล้วข้อมูลทั้งหมดของ Twitter จะไหลลงกิ่ง Twitter ข้อมูลของ TikTok จะไหลลงกิ่ง TikTok ไปเรื่อย ๆ คุณจะเห็นว่านั่นคือจุดที่ switch node ทำงาน

สำหรับ if node มันก็แค่ true หรือ false เป็นตัวเลือกแบบไบนารีที่มีเงื่อนไข ส่วน switch node ทำให้คุณปรับแต่งได้มากกว่าเล็กน้อยเทียบกับ if node ที่ค่อนข้างตรงไปตรงมา แต่ความเรียบง่ายย่อมขยายสเกลได้เสมอ ผมมักเลือกใช้ if node เสมอ นี่คือทั้งหมดของวิดีโอนี้ครับ เจอกันวิดีโอหน้า
