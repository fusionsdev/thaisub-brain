## บทนำ

วิดีโอนี้อธิบายความต่างระหว่าง Vector Database (ฐานข้อมูลเวกเตอร์) กับ SQL Database (ฐานข้อมูลแบบตาราง) และอธิบายว่า RAG (Retrieval Augmented Generation) คืออะไร ทำงานอย่างไร และทำไมธุรกิจถึงควรใช้มัน — แทนที่จะอ่านเอกสารทั้งเล่มทุกครั้งที่ถามคำถาม RAG จะเก็บข้อมูลตามความหมาย แล้วค้นหาคำตอบที่ตรงกับคำถามที่สุดโดยไม่ต้องอ่านทุกอย่าง

## คำแปลเต็ม

ว่าไงครับทุกคน? ยินดีต้อนรับสู่วิดีโอนี้ เราจะพูดถึง Vector Storage กับ SQL Storage เรื่องนี้สำคัญมากๆ เพราะคุณต้องเข้าใจว่า ควรใช้แบบไหนกับกรณีไหน เช่น ถ้าผมแค่ใส่ตัวเลขเมตริกส์ลงในตาราง Airtable ผมคงเลือกใช้ SQL มากกว่า Vector Database แต่ถ้าผมต้องค้นหาแบบ semantic — คือมองหาความหมายที่เกินกว่าคีย์เวิร์ด — ผมจะใช้ Vector ผมจะอธิบายให้ฟังละเอียดขึ้นอีกหน่อย แต่แต่ละแบบมีกรณีการใช้งานที่ต่างกัน

แล้ว Vector Database คืออะไรกันแน่ และ SQL คืออะไร? พูดง่ายๆ SQL Database ก็คือแถวกับคอลัมน์ มันคือตารางแบบที่คุณเห็นใน Google Sheets หรือ Airtable ข้อมูลทั้งหมดอยู่ในรูปแบบแถวกับคอลัมน์ เมื่อ AI อย่าง Claude Code ไปค้นหาใน SQL มันจะค้นจากสองอย่างคือ ตัวเลขและคีย์เวิร์ด เช่น ถ้าผมอยากได้วิดีโอ 10 อันดับแรกที่เกี่ยวกับ Claude มันก็จะค้นหาคำว่า Claude แล้วเจอเรคคอร์ดที่เกี่ยวข้องทั้งหมด จากนั้นกรองเอาท็อป 10 กลับมา นั่นคือ SQL — มันทำ keyword search และ numerical search และมันตรงไปตรงมา เป็นมิติ 2 มิติ มีคอลัมน์ คิดถึง Google Sheets ก็ได้ นั่นคือ SQL Database

ส่วน Vector Database — ตั้งใจฟังนะ อันนี้อาจฟังดูงงมากถ้าคุณไม่เคยใช้ฐานข้อมูลมาก่อน Vector base ไม่ได้เก็บข้อมูลในรูปแบบแถวกับคอลัมน์ แต่มันเก็บในพื้นที่สามมิติ ประมาณนี้ — เก็บแบบสามมิติ ไม่ใช่แถวอีกต่อไป แต่เหมือนลูกบาศก์ของแถวกับคอลัมน์ ฟังดูเหมือนเวทมนตร์ใช่มั้ย? สิ่งที่คุณต้องรู้คือ Vector Database ใช้สิ่งที่เรียกว่า embeddings — embeddings ก็คือชุดตัวเลขเล็กๆ จำนวนมากที่ดูเหมือนพิกัด และตัวเลขเหล่านี้ถูกเก็บไว้ในพื้นที่สามมิตินี้

ให้ผมโชว์ตัวอย่างจริง นี่คือ SQL Database — เห็นไหม มีแถวกับคอลัมน์เยอะแยะ แต่สิ่งที่คุณจะเห็นตรงนี้คือคอลัมน์ Topic Summary Embedding นี่คือสิ่งที่ embedding หน้าตาเป็นอย่างไร มันคือพิกัดชุดหนึ่ง เหมือนตอนที่คุณใช้ Mac นี่แหละคือสิ่งที่ embedding เป็น — โดยพื้นฐานมันเอาข้อความ เช่น transcript หรือหัวข้อของผม ซึ่งผมเดาว่านี่คือสิ่งที่ผม embed ไว้ แล้วมัน embed ตามความหมาย ไม่ใช่ embed แบบ SQL

คุณจะเห็นตรงส่วนล่างของภาพนี้ มันคือข้อมูลแนวงาน — มีข้อมูลที่ดูเป็นงานชัดเจน ทุกอย่างที่เกี่ยวกับงานถูกเก็บไว้ตรงนี้ ขณะที่ตรงบนนี้เป็นแนวคอมพิวเตอร์ ดูเหมือนรูป YouTube ชอบดูอะไรแบบนั้น มันถูกเก็บไว้ด้านบน ตรงนี้ดูเหมือนหนังสือ ดูเหมือนมีความหมายเกี่ยวกับบ้าน การอยู่อาศัย ทั้งสามอย่างนี้มีความหมายต่างกัน มันจะถูกเก็บไว้ในตำแหน่งที่ต่างกันในโลกสามมิติ ฟังดูแปลก แต่ข้อมูลถูกเก็บแบบนั้นจริงๆ

ตัวอย่างคือ — และนี่คือเหตุผลว่าทำไมต้องใช้แบบนี้แทน SQL — เพราะ SQL ค้นได้แค่คีย์เวิร์ด ถ้าผมอยากหาความหมายบางอย่าง เช่น ในเนื้อหาของผม "ช่วยดึงวิดีโอทุกตัวที่ผมสอนวิธีใช้ Claude Code ทำ thumbnails หน่อย" แต่ในวิดีโอจริงๆ ผมไม่ได้พูดคำเหล่านั้นตรงๆ เป๊ะๆ แต่มันมีความหมายใกล้เคียง สิ่งที่ Vector Storage จะทำคือ มันจะค้นตามความหมาย ไม่ใช่คีย์เวิร์ด แล้วดึงผลลัพธ์ 5 ถึง 10 อันดับแรก ขึ้นอยู่กับว่าคุณตั้งค่าไว้เท่าไหร่ มันจะให้คะแนนตามความใกล้เคียง แล้วดึงออกมาจากฐานข้อมูล

ต่างจาก SQL ที่จะทำ keyword search — ถ้าผมบอกว่า "หาวิดีโอ 10 อันดับแรกที่เกี่ยวกับ Claude Code" และในนั้นมีคำว่า Claude ถูกพูดถึงเป็นพันครั้ง มันจะดึงเรคคอร์ดจำนวนมหาศาลออกมา และ AI model จะกิน context หมดอย่างรวดเร็ว นั่นคือสิ่งที่สำคัญมากที่ต้องรู้ เพราะ Vector Storage มีประสิทธิภาพกว่ามาก

และนี่คือที่มาของ RAG RAG — R-A-G — ถ้าคุณเคยได้ยินชื่อนี้ มันย่อมาจาก Retrieval Augmented Generation ผมคิดว่าน่าจะใช่... ผมไม่อยากให้ข้อมูลผิดพลาด ที่จริงคุณไม่จำเป็นต้องรู้ว่ามันย่อมาจากอะไรด้วยซ้ำ สิ่งสำคัญคือมันทำอะไร — Retrieval Augmented Generation ใช่แล้ว นี่คือสิ่งที่ RAG ทำ: คุณเก็บข้อมูลทั้งหมดของคุณใน Vector Database

ตัวอย่างคือ เรานำเอกสารธุรกิจของคุณมาใส่ เช่น avatar ของคุณ ไกด์การตลาดของคุณ แผนการขายทั้งหมดของคุณ นี่ต่างจากการใส่ในแถวกับคอลัมน์ เพราะเอกสารเหล่านี้มีเป็นแสนเป็นพันหน้า สิ่งที่เราทำได้คือ — เราใส่ลงใน SQL ไม่ได้ เพราะทุกครั้งที่บอกว่า "อ่านไกด์ marketing avatar ของฉันหน่อย" มันจะไปดึงทั้งไกด์มาอ่านทั้งหมด ซึ่งเราไม่ต้องการแบบนั้น เราถามคำถามเฉพาะเจาะจงเกี่ยวกับเอกสารเฉพาะสักฉบับ

สิ่งที่ RAG จะทำคือ มันจะเก็บทั้งหมดนี้ตามความหมายในพื้นที่สามมิติ และเมื่อผมถาม มันก็มีตัวเลขพิกัดเหล่านี้อยู่แล้ว มันจะเข้าไปค้นหาตามความหมาย แล้วเจอคำถามที่ตรงกัน หรือคำตอบที่ตรงกับคำถามของฉัน โดยไม่ต้องอ่านทั้งเอกสาร นี่คือจุดที่มันทรงพลังมหาศาลสำหรับธุรกิจ เพราะผมสามารถต่อมันเข้ากับแชทได้ เช่น ผมต่อ CC (Claude Code) เข้าไป แล้วถ้าผมคุยกับคุณ — นี่คือผม นี่คือ CC — CC จะเข้าไปค้นหาส่วนที่ตรงกันเป๊ะ

ตัวอย่างคือ ผมใช้คอมมูนิตี้ของผมเป็นตัวอย่าง เพราะโรงเรียนตามไม่ทันเทคโนโลยีนี้มา 30 ปีแล้ว สมมติว่าผมเก็บแผนการสอนทั้งหมดไว้ใน RAG นี้ ใน Vector Database ทุกอย่างอยู่ที่นั่น แล้วสิ่งที่ผมจะใช้คือ — สมมติว่าคุณมีคำถาม "ฉันจะใช้ Claude Code สร้าง RAG ได้ยังไง?" แทนที่จะไล่ดูทีละอัน ค้นหาคีย์เวิร์ด มันจะรู้ว่าคำตอบถูกเก็บไว้ตรงไหน มันจะข้ามทุกอย่างที่ไม่เกี่ยวข้อง แล้วดึงบรรทัดนี้ที่ตอบคำถามกลับมาให้ผู้ใช้ มันตอบคำถามคุณได้เลย

มันค้นหาความหมายโดยพื้นฐาน มันทรงพลังมากๆ เราจะได้สร้างระบบเหล่านี้ด้วยกัน ผมคิดว่าผมจะทำใน live build เพื่อโชว์ให้ดูว่ามันทำงานยังไงกับ Claude — เวลาคุณเก็บเอกสารและอะไรต่างๆ แค่คุยกับมันเรื่องการสร้าง RAG agent แล้วมันจะทำทุกอย่างให้ เหมือนที่ผมโชว์ให้ดู คุณมี SQL ของคุณ นี่คือความต่างโดยรวม

ผมรู้ว่ามันฟังดูงงมาก มันก็งงมากสำหรับผมเหมือนกันตอนแรก แต่พอคุณเรียนไปเรื่อยๆ ตามเทคโนโลยีนี้ คุณจะเข้าใจมากขึ้นเรื่อยๆ และเห็นความสำคัญของ Vector Storage เทียบกับ SQL ซึ่งจริงๆ แล้วมันคือฐานข้อมูลสองแบบเดียวที่ผมใช้ ผมเท่าที่จำเป็นต้องใช้ นั่นคือทั้งหมดสำหรับวิดีโอนี้ เจอกันวิดีโอหน้าครับ
