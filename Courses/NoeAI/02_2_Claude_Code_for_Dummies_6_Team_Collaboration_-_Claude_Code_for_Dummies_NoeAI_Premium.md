## คำแปลเต็ม

ยินดีต้อนรับสู่บทเรียนนี้ครับ ถึงตอนนี้คุณได้ตั้งค่า Claude เสร็จแล้ว เชื่อมต่อแล้ว และเข้าใจระบบไฟล์ของคุณแล้ว ตอนนี้เราจะมารวมทุกอย่างเข้าด้วยกันเพื่อการทำงานเป็นทีมครับ ถ้าคุณทำงานในบริษัท และมีเพื่อนร่วมทีมหลายคน ทำงานในแผนกเดียวกัน หรือธุรกิจเดียวกัน เพื่อให้ทุกคนติดตามงานกันได้ แทนที่จะต้องส่งข้อความใน Slack บอกว่า "ช่วยส่งอันนี้ให้หน่อยได้ไหม?" แล้วก็ต้องรอเป็นชั่วโมงกว่าจะได้ไฟล์จากใครสักคน — สิ่งที่คุณทำได้จริงๆ คือใช้ GitHub ในการ pull และ push การเปลี่ยนแปลงครับ

การ push การเปลี่ยนแปลง อย่างที่เราเคยพูดถึงในบทเรียนก่อนหน้า ก็คือ: ผมทำอะไรบางอย่างบนคอมพิวเตอร์ของผม แล้วอัปโหลดมันขึ้น GitHub ครับ ผมอยู่ที่คอมพิวเตอร์ตรงนี้ แล้วก็ push ขึ้นไป เช่น สมมติว่าผมทำเสร็จแล้ว — ผมคือ Noah นะ ผม push ขึ้น GitHub สมมติว่าผมมีเพื่อนร่วมทีมอีกคน ชื่อ John — John อยู่ในทีมเดียวกัน เราทำงานในเรื่องเดียวกัน แต่เขาแยกทำงานส่วนของเขาเอง ถ้า John อยากเห็นว่าผมกำลังทำอะไร และมีการเปลี่ยนแปลงอะไรบ้าง เขาก็สามารถทำ pull request ได้ เขาสามารถ pull ได้ พอผม push งานเสร็จ John ก็ pull ไปใช้ได้เลย

แทนที่ผมจะต้องไป Slack แล้วถามว่า "ช่วยส่งเอกสารนี้ให้หน่อยได้ไหม? หรือช่วยส่งไฟล์ที่อัปเดตแล้วให้หน่อย" — เราก็แค่ push ไฟล์ที่อัปเดตขึ้น GitHub แล้วเขาก็ pull ไปใช้ได้โดยตรง และมันก็วนแบบเดียวกันทั้งสองทาง: เขาแก้ไขงานของเขา แล้ว push แล้วผมก็ pull แล้วผมก็เห็นได้ชัดเจนว่าเขากำลังทำอะไรอยู่ ซึ่งน่าสนใจมาก นี่คือเรื่องของ push เทียบกับ pull ครับ

ถ้าคุณอยากเพิ่มเพื่อนร่วมทีมเข้าไปใน GitHub repo เพื่อให้เขาเข้าถึงได้ — จริงๆ แล้วง่ายมากครับ สิ่งที่คุณต้องทำคือ คุณมีสิ่งที่เรียกว่า contributors (ผู้มีส่วนร่วม) contributors คือคนที่ทำงานใน repo นี้ และมีสิทธิ์เข้าถึง ถ้าคุณเคยใช้ Google Drive มันก็เหมือนกับการตั้งค่าสิทธิ์การแชร์นั่นแหละ เหมือนกันเป๊ะ ตัวอย่างเช่น ถ้าผมอยากเพิ่ม Tiffany เข้ามา สิ่งที่ผมต้องทำก็คือ ไปที่ repo นั้น แล้วไปที่การตั้งค่า แล้วค้นหาด้วยอีเมลหรือชื่อ แล้วก็ส่งคำเชิญไป เมื่อนั้นเธอก็จะมีสิทธิ์เข้าถึง repo นี้แล้วครับ

และสิ่งเดียวที่พวกเขาต้องทำเพื่อดาวน์โหลดไฟล์ทั้งหมด คือการ clone repo — จำจากบทเรียนก่อนหน้าได้ไหม? พอพวกเขามีสิทธิ์เข้าถึง แล้วเชื่อมต่อกับ Claude Code แล้ว ก็แค่เข้าไปใน Claude Code แล้วถามว่า "ช่วย clone repo นี้ให้หน่อย" เหมือนที่ผมโชว์ในวิดีโอที่แล้ว แค่ให้ URL ของ repo ไป แล้วมันจะดาวน์โหลดทุกอย่างมาให้ครับ

ถ้าคุณจ้างคนใหม่ และอยากให้เขาตามงานทันเร็วที่สุด — อันนี้ฉลาดมากเลย คุณให้เขาตั้งค่า Claude ของตัวเอง ให้ดาวน์โหลดระบบไฟล์ทั้งหมดที่ทีมคุณใช้ทำงาน แล้วคุณก็แค่ให้พนักงานคนนั้นคุยกับ Claude ว่า "ผมเพิ่งสมัครเป็นพนักงานที่นี่ ช่วยอัปเดตทุกอย่างให้ผมหน่อย ผมอยากเรียนรู้ทุกอย่างเกี่ยวกับธุรกิจนี้" และเพราะทุกอย่างอยู่ในระบบไฟล์ ไม่ว่าจะเป็นวิธีการทำงานทั้งหมด ทุกสิ่งทุกอย่าง — Claude สามารถสอนพนักงานคนนี้ได้ทั้งหมด แทนที่จะต้องนั่งฝึกอบรมใครสักคน คุณไม่จำเป็นต้องทำแบบนั้นเลย

ตัวอย่างจริง: ผมเคยฝึกคนให้มารับช่วงต่อเอเจนซีโฆษณาแบบ done-for-you ของผม ซึ่งมีบัญชีโฆษณา 16 บัญชี เพราะผมไม่อยากทำมันต่อแล้ว สิ่งที่ผมทำคือ ผมใส่ความรู้ทั้งหมดของผมลงใน repo แล้วให้เขา clone มัน เขาดาวน์โหลด แล้วก็เริ่มคุยกับมัน — คุยกับ Claude ว่า "ข้างในนี้มีอะไรบ้าง? อันนี้ทำงานยังไง? อันนั้นทำงานยังไง? ช่วยอธิบายให้ผมฟังหน่อย สอนผมเกี่ยวกับเรื่องนี้หน่อย" แล้วเขาก็ตามงานทันเร็วมาก ผมแทบไม่ต้องนัดประชุมกับเขาเลยสักครั้ง ถ้าเราไม่ได้ใช้ GitHub เรื่องนี้คงต้องใช้การประชุมปฐมนิเทศถึง 9 รอบ ต้องใช้ข้อความ Slack เป็นร้อยๆ ข้อความเพื่อค้นหาเอกสาร แล้วส่งเข้าไปในคอร์สต่างๆ แต่แทนที่จะเป็นแบบนั้น ผมแค่ให้ repo ไปหนึ่งอัน แล้วเขาก็พร้อมทำงานเลย มันมีคุณค่ามากจริงๆ ครับ

แผนการสอนอาจไม่ได้อธิบายเรื่องนี้ แต่ workflow จริงๆ คือแบบนี้: เมื่อสมาชิกทีมมีสิทธิ์เข้าถึงแล้ว และ clone แล้ว สิ่งที่คุณและทีมต้องทำให้เป็นนิสัยคือการ push การเปลี่ยนแปลงทุกวัน เมื่อไหร่ก็ตามที่มีใครทำงานเสร็จ พวกเขาต้อง commit และ push สิ่งที่ทำในวันนั้นเข้าสู่ repo และนี่ก็เป็นวิธีที่ดีมากในการทำ end-of-day automation (ระบบสรุปงานปลายวัน) ด้วย — ถ้าอยากรู้ว่าสมาชิกทีมทำอะไรบ้าง คุณก็แค่ดูว่าพวกเขา commit และ push อะไรไป ถ้าพวกเขาไม่ commit ไม่ push แล้วมาอยู่ในทีมคุณทำไม? คุณสอนให้พวกเขา commit แล้วโชว์วิธีการนี้ให้ดู แล้วคุณจะรู้ว่าวันนั้นพวกเขาทำอะไรบ้าง

แล้วคุณก็ pull การเปลี่ยนแปลงทั้งหมดที่พวกเขาทำ แล้วคุยกับ Claude ว่า "X กับ X วันนี้ทำอะไรบ้าง? ช่วยแยกแยะให้ผมดูหน่อยว่าพวกเขาทำอะไรบ้าง" ประมาณนั้น แล้วคุณก็จะเห็นได้ชัดเจนว่าทุกคนกำลังทำอะไรอยู่ นี่คือทั้งหมดของเรื่อง push-pull และการทำงานร่วมกันเป็นทีมด้วย GitHub ครับ เป็นเนื้อหาที่ให้ความรู้มาก หวังว่าทุกคนจะได้คุณค่าจากมันเยอะๆ นะครับ ถ้ามีคำถามอะไรก็คอมเมนต์บอกได้ แล้วเจอกันในบทเรียนถัดไปครับ
