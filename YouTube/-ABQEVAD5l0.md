## ประเด็นหลัก
- DeepSeek Harness เพิ่งปล่อย developer preview เวอร์ชัน 0.1 กวาดดาว GitHub ไป 113,000 ดาวใน 2 วัน (ตอนนี้ 136K) ส่วน Hermes จาก Nous Research มี 226,000 ดาวจากการสะสม 6 เดือน
- แนวคิดหลักของ DeepSeek Harness คือ "ทุกอย่างคือปลั๊กอิน" (Everything is a plugin) สร้างบนเฟรมเวิร์ก Cordis ที่ผ่านการใช้งานจริงจากโปรเจกต์แชทบอท Koishi มาหลายปี
- DeepSeek Harness เหมาะกับงานเขียนโค้ดมากกว่า ใช้งานง่าย พังน้อยกว่า ตั้งโมเดลง่าย และดู/ดาวน์โหลด session logs ได้ง่าย
- ในการทดสอบจริง DeepSeek Harness ให้ผลลัพธ์และความเร็วในการตอบที่ดีกว่า ส่วน Hermes มัก time out กับงานโค้ดใหญ่ๆ และเหมาะกับงานตามกำหนดครั้งเดียวมากกว่า
- จุดเด่นของ Hermes คือระบบความจำสามชั้น (three-layer memory system) กับวงจรพัฒนาตัวเอง (self-improvement loop) ที่บันทึกสิ่งที่เรียนรู้เป็นสกิล
- Hermes เชื่อมต่อได้หลายช่องทาง (Telegram, WhatsApp, Discord, Microsoft Teams, iMessage) แต่ UI ซับซ้อนกว่าและพังบ่อยกว่า
- การสร้าง custom workflow ใน Hermes (เช่น Hermes Oracle, Hermes Muse) ต้องเขียนโค้ดเองหลายชั่วโมง ส่วน DeepSeek Harness ทำได้ด้วย creator mode ในเซสชันใหม่
- DeepSeek Harness โฮสต์ในเครื่องแบบเว็บไซต์ ทำให้เข้ากับเวิร์กโฟลว์ในเบราว์เซอร์โดยไม่ต้องเปิดแอปเพิ่ม
- ผู้พูดแนะนำ DeepSeek Harness สำหรับมือใหม่และงานโค้ด แต่ใช้ทั้งสองตัวร่วมกันใน Agentic Operating System เพื่อให้แต่ละตัวทำในเลนที่ถนัด
- เทรนด์ที่เห็นคือโปรเจกต์โอเพนซอร์สใหญ่ขึ้นเรื่อยๆ ทั้งเครื่องมือและโมเดลฟรี (เช่น DeepSeek V4 Flash ผ่าน OpenCode) ทำให้ใช้เอเจนต์ได้แทบไม่เสียเงิน

## ความเห็นสรุป
คลิปนี้ให้การเปรียบเทียบที่ใช้งานได้จริงระหว่างเอเจนต์โอเพนซอร์สสองตัว ทั้งความยืดหยุ่นแบบปลั๊กอินและความง่ายของ DeepSeek Harness กับระบบความจำและการเรียนรู้ของ Hermes โดยสรุปว่าขึ้นอยู่กับงานที่ใช้ ควรเลือก DeepSeek Harness ถ้าต้องการความเสถียรและงานโค้ด และใช้ทั้งคู่ร่วมกันได้ดีที่สุดผ่านระบบแดชบอร์ดเดียว อย่างไรก็ตาม ช่วงต้นและท้ายคลิปมีการโปรโมตชุมชน AI Profit Boardroom ของผู้พูดเอง ซึ่งควรแยกออกจากเนื้อหาหลัก
