## ประเด็นหลัก

- **Profile คืออะไร:** profile ไม่ใช่แค่การตั้งค่า แต่เป็น Hermes Agent ทั้งตัวที่แยกออกมาสมบูรณ์ มี config โมเดล ความจำ skills gateway บุคลิก และแม้แต่เบอร์โทรศัพท์เป็นของตัวเอง อยู่ใต้ไดเรกทอรี `.hermes/profiles/<ชื่อ>` ซึ่งต่างจาก sub-agent ที่เป็นตัวช่วยชั่วคราวภายในเซสชันเดียว
- **เหตุผลที่ต้องมี:** การรันเอเจนต์สองตัวจาก Hermes home เดียวกันจะทำให้ฐานข้อมูล SQLite เสียหายเพราะ gateway แย่งกันใช้ profile จึงเป็น "หนึ่ง home ปิดผนึกต่อเอเจนต์หนึ่งตัว" เพื่อกันสถานะปนกัน
- **สร้าง คัดลอก สลับ ลบ:** ทำได้ 3 ทางคือ CLI (`Hermes profile create <ชื่อ>`, `coder chat`, `profile use`) เว็บแดชบอร์ด (สร้าง/clone/เปลี่ยนโมเดล/แก้ soul/เปลี่ยนชื่อ) และเดสก์ท็อปแอป การลบโปรไฟล์ต้องปิดเดสก์ท็อปแอปก่อน เพราะโปรไฟล์ที่กำลังทำงานจะถูกล็อก
- **รันหลายตัวพร้อมกัน:** แต่ละ profile รัน gateway ของตัวเองด้วย bot token ของตัวเอง (เช่น coder ใน Slack และผู้ช่วยใน Telegram พร้อมกัน) แต่ถ้าสองโปรไฟล์ชี้ไปที่ bot token เดียวกัน ตัวที่รันทีหลังจะ error — ตัวที่รันก่อนได้สิทธิ์ก่อน
- **ข้อควรระวังสำคัญ:** profiles แยกสถานะแต่ไม่ได้แซนด์บ็อกซ์คอมพิวเตอร์ ต้องใช้ `cwd` ปักหมุดไดเรกทอรีทำงานร่วมกับ sandbox backend (Docker หรือ SSH) จากโมดูล 2 เพื่อการแยกที่จริงจัง
- **แชร์เอเจนต์ทั้งตัว:** `Hermes profile export` สร้าง snapshot เป็น .tar.gz และ `import` กู้คืนได้ หรือติดตั้งจาก Git repo ผ่าน `Hermes profile install` — ใช้แชร์ "พนักงานดิจิทัล" แบบแพ็กเกจได้
- **Kanban board คือทีมที่ทนทาน:** กระดานเป็นไฟล์ SQLite (kanban.db) ที่อยู่รอดการรีสตาร์ท เป้าหมายถูกแยกย่อยโดยโมเดล Kanban decomposer เป็นงานย่อย แล้วจัดเส้นทางให้โปรไฟล์ที่เหมาะสมโดยอ่านจากคำอธิบายโปรไฟล์ (ไม่ใช่อ่านชื่อ)
- **คอลัมน์ของกระดาน:** triage → waiting on dependencies → scheduled → ready → in progress → blocked (รอมนุษย์ปลดล็อก) → review → done และงานรันบนโมเดลของโปรไฟล์ที่เป็น assignee — ตั้งโมเดลต่องานไม่ได้ ต้องสร้างโปรไฟล์ใหม่แทน
- **การสาธิตจริง:** ทีม 3 โปรไฟล์ (researcher = GPT 5.5, coder = GPT 5.5, writer = GLM 5.2) ทำงาน "วิจัย ML ในวงการกีฬา สร้างต้นแบบ และเขียนรายงาน" สำเร็จด้วยกันเอง โดย researcher วิจัย → ส่งต่อ coder สร้าง Python prototype → ถึงจุด blocked รออนุมัติมนุษย์ → writer เขียนรายงาน
- **โมดูล 10 สัปดาห์หน้า:** ตอนสุดท้ายของซีรีส์ว่าด้วยเรื่องความปลอดภัย (security) เพราะเอเจนต์ที่สร้างได้สามารถแตะไฟล์ เข้าถึงบัญชีเชลล์ และใช้จ่ายเงินได้

## ความเห็นสรุป

โมดูลนี้ปิดช่องว่างระหว่าง "เอเจนต์ตัวเดียว" กับ "ทีมเอเจนต์ถาวร" ได้อย่างเป็นรูปธรรม โดยอธิบายทั้งกลไกเบื้องหลัง (SQLite, token lock, การจัดเส้นทางด้วยคำอธิบาย) และวิธีใช้งานจริงครบทุกช่องทาง (CLI, เว็บแดชบอร์ด, เดสก์ท็อปแอป) พร้อมข้อควรระวังเรื่องความปลอดภัยที่หลายคนมองข้าม การสาธิตทีม 3 ตัวที่ทำงานชิ้นเดียวเสร็จโดยมีมนุษย์แทรกแซงเฉพาะจุดที่ต้องตรวจทาน ช่วยให้เห็นภาพการใช้งานจริงได้ชัดเจน เหมาะสำหรับคนที่อยากต่อยอดจาก sub-agent ไปสู่เวิร์กโฟลว์แบบ multi-agent ที่ต้องอยู่รอดการรีสตาร์ท
