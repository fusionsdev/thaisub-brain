## คำแปลเต็ม

ว่าไงครับทุกคน? ยินดีต้อนรับสู่ Live Build เราจะใช้ Claude Code สร้างระบบ polling ข้อมูล Instagram ระบบนี้จะดึงเมตริกจาก Instagram ทุกวัน เพื่อให้เรารู้ว่าบัญชี Instagram ของเราทำผลงานยังไง และที่จริงผมสร้างมันไว้ใช้ส่วนตัวแล้ว มีข้อมูลหลายร้อยชิ้นบนคอนเทนต์ที่ทำผลงานดีที่สุดของผม ดังนั้นวันนี้เราจะสร้างมันแบบสด ๆ ให้คุณเห็นวิธีที่ดีที่สุดในการสร้างบน n8n ด้วย Claude Code แบบนั้น เริ่มกันเลย

สิ่งแรกที่อยากทำ คือผมจะโชว์ให้ดูแบบสด ๆ ไม่ได้สอนแบบเป็นขั้นตอน แต่ให้คุณดูผมทำงานจริงและกระบวนการคิดของผม ผมคุยกับตัวเองเยอะมากว่าทำไมถึงทำแบบนี้ แต่เข้าเรื่องกันเลย ผมอยากดึงเมตริกทั้งหมดของผมทุกวัน โดยทำอะไรง่าย ๆ สุด ๆ สองสิ่งที่เราต้องการคือ Meta app setup

ถ้าคุณยังไม่ได้ตั้งค่า Meta app ของตัวเอง ดูตรงนี้ก่อน เราอยู่ตรงไหน? ใช่ ถ้าคุณยังไม่ได้ไปสร้างแอปของคุณเอง ผมให้รายละเอียดเต็มไว้ใน Content System แล้ว ผมสอนวิธีสร้างแอปของคุณเอง ซึ่งจะให้คุณเข้าถึง Instagram insights เพื่อดึงข้อมูลจากบัญชี Instagram ของคุณทุกวัน เพื่อให้ได้เมตริกทั้งหมดของวิดีโอทุกตัวที่เข้ามา

ผมจะไม่เสียเวลาพาคุณผ่านการตั้งค่าแอปทั้งหมด มันเป็นวิดีโออีกเรื่องหนึ่งที่ผมอัดไว้ ดังนั้นเตรียมมันไว้ให้พร้อม เราจะต้องใช้มัน แล้วเราก็ต้องมี Airtable ผมมี Airtable อยู่แล้ว สิ่งที่ผมจะทำคือดาวน์โหลดมันแล้วใส่เข้าไปในเวิร์กโฟลว์ เดี๋ยวทำเลยให้ดู เราจะทำ CSV และดาวน์โหลดมัน ไปกัน บูม เราจะอัปโหลดมัน ใน live นี้ผมจะวาง CSV ไว้ข้างล่างเพื่อให้คุณดาวน์โหลดเองและลองทำตาม

แต่มาสร้างอันใหม่ตรงนี้ ดูเหมือนเรามีทุกอย่างที่ต้องการแล้ว แค่ต้องปรับสองสามอย่าง เจ๋ง caption ผมไม่ต้องการข้อมูลทั้งหมดนี้ มาทำตรงนี้ แทนที่จะทำอะไรโง่ ๆ แบบนั้น มาทำแบบนี้ แล้วลบ record ที่เลือกทั้งหมด 445 records บ๊ายบาย เจ๋ง

เรามี Instagram media เราต้องแน่ใจว่าทุกอย่างอยู่ใน permalink ที่ถูกต้อง caption outlier score engagement rate engagement rate จะเป็นสูตร เรายังไม่รู้ว่าสูตรอะไร ตั้งเป็นตัวเลขไว้ก่อนจนกว่าเราจะรู้ โอเค สำคัญที่ผมต้องตั้งค่าทั้งหมดนี้ไว้ คุณดาวน์โหลดไปแล้วสิ่งเดียวกันน่าจะเกิดขึ้น ตั้งเป็นรูปแบบตัวเลข ตัวเลข เยี่ยม เจ๋ง และ completion rate ก็ต้องเปลี่ยนด้วย re-watch rate total transcript ฮุก topic summary ใช่ และ stats link ก็ต้องเปลี่ยนด้วย มันเป็นลิงก์ไปหา record อื่นที่ยังไม่มี ลบมันทิ้ง เพราะบทเรียนนี้ผมจะไม่ลงรายละเอียดขนาดนั้น โอเค ดูเหมือนเรามี data points ครบแล้ว ซึ่งเยี่ยม ผมต้องแน่ใจว่ามันมีของผม

ตอนนี้สิ่งที่ผมจะทำคือ ตอนที่ prompt Claude ให้สร้างอะไรใน n8n ผมทำสิ่งที่เรียกว่า GSD มันคือ Get Shit Done repo ถ้าคุณไม่รู้จัก ให้ไปดาวน์โหลด ผมคิดว่าให้คุณในคอร์ส Claude Code แล้ว แต่มันจะถามคำถามเยอะมากเกี่ยวกับบริบทของโปรเจกต์ที่คุณกำลังสร้าง ถ้าเรากำลังสร้าง build ที่มีหลายเวิร์กโฟลว์ซับซ้อนมาก คุณควรใช้มัน แต่ในบทเรียนนี้เรากำลังสร้างระบบ polling Instagram ง่าย ๆ เราจึงไม่ต้องใช้มัน

แต่สิ่งที่เราต้องทำคือเข้าไปในโหมด /plan แล้วอธิบายสิ่งที่เรากำลังทำ โอเค "เรากำลังสร้างเวิร์กโฟลว์ polling Instagram ที่จะใช้ Meta app ที่เราสร้างไว้ และดึงเมตริกคอนเทนต์ Instagram ของผมทุกวัน มันจะรันตอนหกโมงเช้า ดึงเมตริกของวัน แล้วอัปโหลดเข้า Airtable แบบ upsert จะสร้าง record ใหม่สำหรับวิดีโอใหม่ และอัปเดต record เก่าของวิดีโอนั้นทุกวัน ผมสร้าง Airtable และเวิร์กโฟลว์ที่เราจะใช้ไว้แล้ว และผมเข้าใจว่าเราสร้างสิ่งนี้มาก่อนแล้ว ดังนั้นเราควรใช้บทเรียนที่มี แต่ผมกำลังทำวิดีโอสำหรับคอมมูนิตี้พรีเมียมตอนนี้ อย่าเขียนทับอะไรที่เราทำมาก่อน เราจะสร้างใหม่เป็นตัวอย่างเพื่อโชว์วิธีสร้าง แต่ถามคำถามที่คุณต้องการก่อนเริ่ม build"

เจ๋ง จากนั้นผมจะเข้าไป เพื่อความชัวร์กับ Airtable นี้ ผมแค่อยากแน่ใจว่ามันไม่ทำผมพัง โอเค เราจะวางไฟล์นี้ แล้วทำ workflow ผมอยากแน่ใจว่ามันทำงานในที่เฉพาะเหล่านี้ แต่คุณไม่ต้องทำแบบนั้น ทุกครั้งที่คุณเข้า Claude Code คุณควรเข้าโหมด plan ด้วย /plan สิ่งที่มันจะทำคือถามคำถามผมก่อนที่จะสร้างอะไรจริง ๆ ดูสิ มันกำลังรวบรวมบริบทเกี่ยวกับ Airtable, ชื่อตอนจบ, Instagram puller ที่มีอยู่ ก่อนที่จะถามคำถาม

มันรวบรวมบริบทจากสามส่วน: Airtable ฯลฯ เจ๋ง มันรวบรวมบริบทจากสิ่งที่รู้อยู่แล้ว ผมจะให้เวิร์กโฟลว์และ Airtable base กับคุณ เพื่อให้คุณดาวน์โหลดและให้มันได้ คุณจะได้บริบทเดียวกันกับที่ผมเริ่ม ดูเหมือนมันกำลังอ่านไฟล์ทั้งหมดตาม API ที่เราจะต้องใช้ เจ๋ง ทำงาน มันดึงบริบททั้งหมดของโปรเจกต์ มันอยากสร้าง Airtable ที่นำเข้า กับ n8n และบทเรียนที่มีอยู่ก่อน แล้วมันจะถามคำถามสองสามข้อก่อนที่ผมจะปล่อยแผนนี้

"นี่เป็น demo สำหรับคอมมูนิตี้พรีเมียม ควรข้าม Supabase ไปเลยไหม?" เราจะไม่ใช้ vector storage base เพื่อความง่าย เราใช้แค่ Airtable "ควรสร้างไปป์ไลน์มากแค่ไหน? แค่ดึงเมตริกรายวันหรือรวมการวิเคราะห์ทรานสคริปต์ด้วย?" เราจะทำการวิเคราะห์ทรานสคริปต์ในวิดีโอหน้าเมื่อเราสร้างเวิร์กโฟลว์วิเคราะห์วิดีโอ เวิร์กโฟลว์นี้จะ trigger เวิร์กโฟลว์วิเคราะห์หลังจากลูปเสร็จ เก็บไว้ในแผน แต่เรากำลังสร้างตัวดึงเมตริกก่อน "Airtable เรียกว่าตาราง imported และมี CSV ควรเปลี่ยนชื่อให้ดูดีขึ้นสำหรับ demo ไหม?" อะไรก็ได้ "Meta Graph header auth ตั้งค่าไว้แล้วใน n8n หรือต้องทำใหม่?" ตั้งไว้แล้ว โอเค เยี่ยม

มันถามคำถามทั้งหมดที่มันต้องรู้ นั่นแหละคือสิ่งที่สำคัญที่สุด เวลาคุณสร้างอะไร ให้มันถามคำถามคุณเยอะ ๆ การสร้างจริงมันง่าย สิ่งที่ใช้เวลามากที่สุดคือแผน ถ้าคุณใช้เวลาเยอะกับการให้มันถามคำถามทั้งหมด ถ้าคุณใช้ Get Shit Done มันช่วยได้มาก อันนี้เล็กกว่า คุณไม่ต้องใช้ แต่เวลาสร้างของที่ใหญ่กว่า คุณควรใช้เวลาเยอะกับการวางแผน ให้แน่ใจว่ามันวางแผนทุกอย่างถูกต้อง ไม่ใช่แค่กดปุ่มมั่ว ๆ แล้วฟังดูดี คุณต้อง iterating ตลอดเวลา

ดูสิ มันกำลังเข้าโหมด plan มันเข้าอยู่ตรงนี้ กล่องสีเขียวน่าจะเด้งขึ้นมา แล้วมันจะให้แผนทั้งหมดตั้งแต่ต้นจนจบว่ามันจะทำอะไร แล้วเราจะอ่านและตรวจสอบให้ถูกต้องก่อนที่จะ execute และ launch แจ้งให้ทราบว่ามันใช้เวลาสักครู่ แต่มันกำลังลงลึกมากในแผน มันเรียกเครื่องมือเยอะมากตอนนี้ มันกำลังรวบรวมทุกอย่างและวางแผนทั้งหมด เห็นไหมมันแสดงตัวเลขแบบ 5, 6.9 มันกำลังคิด เจ๋ง ตอนนี้ดูเหมือนมันวางแผนเสร็จแล้ว และมันละเอียดมาก เราจะอ่านดู โอเค

"Instagram Poller building เราปฏิเสธผ้าใบเปล่า" ผมแค่ต้องแน่ใจว่ามันถูกต้อง เราได้ ZGSE ลงท้าย นั่นคือสิ่งที่เราต้องการ แล้วเรามี Airtable 6A และ ZH ดูเหมือนมันอาจ... มาดูว่ามันทำอะไร มันยังไม่ได้ทำอะไร เพราะเราอยู่ในโหมด plan ดูว่ามันดึงขึ้นมาไหม "View is NLO" ผมไม่เห็นว่ามันอยู่ไหน โอเค นั่นคือตารางตรงนั้น เยี่ยม โอเค แล้วเราจะแก้ Airtable ก่อนสร้าง "ปัญหาคือ CSV เปลี่ยนชื่อ แก้ BOM เป็นชื่อฟิลด์หลัก เปลี่ยนฟิลด์ Instagram ID จากตัวเลขเป็น single line text เพราะ Instagram IDs เกิน JavaScript" เข้าใจแล้ว

"สถาปัตยกรรมเวิร์กโฟลว์: schedule trigger เวลาหกโมงเช้า, HTTP request เรียก Instagram media ทั้งหมด, code node กรอง reels ใน 30 วันที่ผ่านมา" ผมไม่อยากใช้ code node ดูตรงนั้น "split into batches, HTTP request trigger เวิร์กโฟลว์วิเคราะห์, loop HTTP และ merge node คำนวณ HTTP requests ไปยัง Airtable upsert กลับ" ผมไม่ชอบแบบนั้น เราจะเปลี่ยน แต่เดี๋ยวดูว่ามันจะเป็นยังไง

"schedule trigger ด้วย cron, HTTP เพื่อดึง Meta stuff, ผมไม่ต้องการ code node flatten paginated results" เราจะดึงเฉพาะ 30 วันที่ผ่านมา แยกเป็น batch ประมวลผลแต่ละ reel นั่นคือลูป "HTTP REST เพื่อดึง reel insights เราจะต้องใช้ HTTP request นั้น, merge บวกคำนวณอัตรา, HTTP REST upsert ไป Airtable แล้ว HTTP REST trigger เวิร์กโฟลว์วิเคราะห์"

นี่คือเหตุผลที่สำคัญที่คุณต้องเรียนคอร์ส n8n จบ ดูนี่สิ Claude Code ชอบใช้ code node แทน native nodes ที่มีอยู่ใน n8n มันบอกว่ามันอยากใช้ code node กรอง reels ใน 30 วัน แต่เราไม่ต้องใช้ code node เลย เราใช้ filter node ซึ่งเป็น native ใน n8n และมันจะกรองให้ ซึ่งตรงไปตรงมา แล้ว HTTP request เพื่อดึง reel insights เราอาจต้องใช้ code nodes เพื่อ merge และคำนวณอัตรา? เราไม่ต้อง ดูตรงนั้น "merge กับ media type engagement rate" ผมไม่รู้ จำเป็นต้องคำนวณ engagement นะ เราจะทำ อันนั้นเป็นการจับที่ดี แต่ผมไม่ต้องให้มันคำนวณจริง ๆ เราจะคำนวณอัตราใน Airtable แล้ว upsert ไป Airtable เราไม่ต้องใช้ HTTP request สำหรับอันนั้น เราใช้โหนด "สร้างหรืออัปเดต record" ได้เลย แล้ว HTTP request trigger เวิร์กโฟลว์วิเคราะห์ เราก็ไม่ต้องใช้เหมือนกัน ดีมากที่คุณเห็นสิ่งนี้ตอนนี้ โอเค

โครงสร้างนี้สมเหตุสมผล แต่หลายโหนดเราไม่ต้องการหรือผิด อันแรกคือโหนดสาม "กรอง reels ใน 30 วัน" เราไม่ต้องใช้ code node กรอง reels เราใช้ native filter node กรอง reels ที่อยู่นอกช่วง 30 วันได้ แล้วแสดงผล สมเหตุสมผล โหนดสี่ "merge บวกคำนวณอัตรา" เราไม่ต้องคำนวณอัตราแบบ live ผมแค่ต้องได้เมตริกพื้นฐานอย่าง reach และ views เข้าไปใน Airtable พออยู่ใน Airtable แล้วผมใช้สูตรคำนวณอัตราพวกนั้นให้ผม โอเค

แล้วคุณมีโหนด "HTTP request เพื่อ upsert ไป Airtable" เราไม่ต้อง เพราะใน n8n มี native node ให้สร้างหรืออัปเดต record เราสามารถใช้ native node ได้ แล้วโหนด "HTTP request trigger เวิร์กโฟลว์วิเคราะห์" เราก็ไม่ต้องใช้ HTTP request เราต้องใช้ execute sub-workflow node "ผมแค่ต้องการให้แน่ใจว่าคุณเรียกใช้สกิล n8n ของคุณและอ่าน reference docs จาก build ก่อนหน้า เพื่อให้เราใช้การเปลี่ยนแปลงทั้งหมดนี้" โอเค

เดี๋ยวก่อน เอาเป็นสี่ บูม นั่นแหละที่ผมต้องการ แล้วดูว่ามีอะไรอีกในนี้ ดูว่ามันมีข้อมูลอะไร "ใช้ graph.facebook.com graph insights some reels error on มันใช้ key learnings ตรงนี้ น่าสนใจ Airtable permalink caption total watch time average watch time saves shares last days live นั่นคือสิ่งที่เราต้องการ" เจ๋ง โอเค เราจะส่งการเปลี่ยนแปลงเหล่านั้นไป

มันสร้างเวิร์กโฟลว์ที่ดีได้ แต่ถ้าคุณไม่รู้เลยว่าคุณกำลังสร้างอะไรและมีเครื่องมืออะไรบ้างใน n8n คุณจะเจอปัญหาแบบนี้ เพราะมันจะประกอบมันขึ้นมาและมันอาจจะทำงานได้ แต่มันเหมือนการสร้างที่ซับซ้อนเกินไป เราอยากได้เวิร์กโฟลว์ที่ง่ายที่สุดเท่าที่จะเป็นไปได้ เพราะยิ่งมีโหนดเยอะ ยิ่งปวดหัวเวลาดูแล เราอยากได้เวิร์กโฟลว์ที่ตรงประเด็น แค่นั้นที่เราต้องการ โอเค

ตอนนี้ดูเหมือนมันกำลังแก้ schema ให้ถูกต้อง เห็นไหมว่ามันกำลังดึงข้อมูลโหนด มันเข้าไปใน reference ทั้งหมดตามที่ผมสั่ง มันไม่ได้โหลดสกิลตั้งแต่แรก นั่นก็เป็นเรื่องปวดหัวเหมือนกัน บางครั้งมันไม่อ้างอิงสกิล มันรู้ว่าเรากำลังสร้างเวิร์กโฟลว์ แต่ทำไมมันไม่เรียกสกิล n8n ผมไม่รู้ บางครั้งคุณต้องบอกมันเอง ดี ตอนนี้ผมมี node schema ที่ถูกต้อง "ให้ผมอัปเดตแผนด้วยการแก้ไขเหล่านั้น" มาดูว่ามันทำอะไร เจ๋ง ดูเหมือนมันกลับมาแล้ว เช็คอีกครั้ง และคุณเริ่มเห็นกระบวนการแล้ว 90% ของอันนี้คือการวางแผน เพราะถ้าคุณวางแผนแม่น คุณจะไม่ต้องมั่วกับการดีบั๊กมาก เราสร้างสิ่งนี้ เราใช้บทเรียนเหล่านั้นทุกวัน

ดูเหมือนมันกำลังทำ breakdown "โหนดหนึ่งคือ schedule trigger" เรากำลังทำ schedule trigger สำหรับ cron "HTTP request เพื่อดึงทุกอย่าง" ทำไมมันทำ max 10 ดูตรงนี้ สมเหตุสมผล "กรองเฉพาะ reels, แยกเป็น batch, HTTP requests เพื่อดึง reel insights เราจะต้องใช้มัน, หกคือ edit fields nodes เพื่อ map metrics" ดี โอเค "ผมรัก edit fields พวกนั้น มันง่ายมาก" นั่นคือสิ่งที่เราต้องการเป๊ะ แล้วมัน map พวกนี้ "แล้ว Airtable upsert ไปยัง Instagram reels" หรืออัปเดต สวยงาม "แล้วโหนด execute trigger key learnings build order" ใช่ นั่นคือสิ่งที่เราต้องการเป๊ะ

filter node คืออะไร? ดูสิ "แยกเป็น batch, กรองเฉพาะ reels, type any node space conditions" โอเค ตอนนี้เราจะ clear context เยี่ยม ตอนนี้มันจะทำงาน มันอยู่ในโหมด plan เต็ม และมันล้างบริบททั้งหมดเพื่อให้มีที่ว่าง ตอนนี้มันจะไป build มาดูว่ามันทำอะไร เจ๋ง

อัปเดตสั้น ๆ ดูเหมือนมันมีแพตเทิร์นทั้งหมด มันสังเกตว่าผมใช้ credential type ต่างออกไปในเวิร์กโฟลว์อื่น ผมมีแพตเทิร์นทั้งหมด "code node สำหรับ insights parsing" ถ้ามันใช้ code ผมจะโกรธนิดหน่อย "แปดโหนด deploy พร้อมการเชื่อมต่อที่ถูกต้อง นี่คือสิ่งที่อยู่บน canvas: ดึง reels ทั้งหมด, loop, trigger analysis" มาดูว่ามันทำอะไร เจ๋ง ดูเหมือนมันทำออกมาแล้ว มัน map เมตริก แต่ใส่ใน code node ทำไมคุณเลือกแบบนั้น? เจ๋ง มันใช้ code node ซึ่งผมไม่ต้องการ ผมถามมันว่าทำไมมันทำแบบนั้น ดูเหมือนมันกำลังอัปเดตโฟลว์ใหม่

พูดง่าย ๆ มันสร้างให้เรา: ตอนหกโมงเช้า มันจะดึงเมตริกทั้งหมดของเรา ดึงข้อมูลทั้งหมดที่เราต้องการ มันจะดึง media แล้วกรองเอาเฉพาะ reels แล้วลูปแต่ละ reel ดูนี่สิ ดูเหมือนมันอัปเดตแล้ว ทำ reset ตรงนี้ ดูว่ามันมีอะไรให้เรา เจ๋ง เอาล่ะ ดูเหมือนมัน map เมตริกแล้ว เยี่ยม เจ๋ง ดูเหมือนมันมี polling ทั้งหมด มันจะดึง reels ทั้งหมด แล้วดูว่ามันดึงการ map ค่า dynamic ของ Airtable ออกมาหรือเปล่า เยี่ยม เจ๋ง มาดูว่ามันทำงานไหม เจ๋ง fetch authorization ดูว่า error code คืออะไร "Error invalid contents" ดูสิ "Invalid character header content authorization" มันต้องเกี่ยวกับ predefined credential type และ media ที่ดูเหมือนข้อมูลบัญชีของผม เราให้อันนี้ "Error ใน Meta node ช่วยอธิบายว่าทำไมสิ่งนี้เกิดขึ้นและวิธีแก้ไข" โอเค ให้ error ทั้งหมดกับมัน

มันเห็นได้เลย ผมไม่ต้องคัดลอกมาตรงนี้ด้วยซ้ำ มันเข้าไปดูเองได้ แต่มันจะประหยัด token ให้ผม ให้ผมคิกอิน มาดูว่ามันทำอะไรให้เรา "น่าจะเป็นแค่ header authentication" ดีที่คุณเห็นสิ่งนี้ นี่คือจุดประสงค์ของ live build เพื่อเห็นว่ามันปวดหัวขนาดไหน "เพราะ Meta Graph API มี bad character ใน token ส่วนใหญ่เป็น trailing new line หรือ carriage return เลือกหนึ่งตัวเลือก: แก้ credential ใน 30 วินาที, รักษา demo ให้สะอาด, เปิด n8n Meta Graph คลิก header เพื่อเลือก แล้ววาง token ใหม่, สลับเป็น query param" โอเค เจ๋ง

มันอยากให้เราวาง token ใหม่และแน่ใจว่า cursor อยู่ท้ายสุด เอาล่ะ ดูสิ "มันบอกว่ามีอะไรบางอย่างผิดกับ header" ผมจะเลือกตัวเลือก B "ช่วยอัปเดตโหนดนั้นหน่อย" มันจะเอา token ที่ถูกต้องให้เรา ขอเอา off screen เพื่อไม่ให้ API keys ผมหลุด เราจะปล่อยให้มันทำงาน แล้วดูว่าวันนี้มันทำอะไรให้เรา โอเค นั่นไม่ใช่สิ่งที่ผมต้องการ เราอยู่ในอีกอันหนึ่ง ผมแค่ต้องแน่ใจว่า token ของผมไม่หลุด ดูเหมือนเรากำลังทำกันอยู่ เจ๋ง มันใส่ token ลงไปแล้ว คุณจะเห็น มันใส่ในนี้ ผมจะไม่เลื่อนลงเพื่อให้คุณไม่เห็น แต่ลองยิงดู

มาดูว่ามันทำอะไร และผมจะโชว์ทริคเจ๋ง ๆ หลังยิงอันนี้ เพราะผมไม่มีความหวังว่ามันจะโอเค ดูเหมือนมันกำลังเรียก มันคิดว่า authorization อัตโนมัติทำงานได้ สิ่งที่ผมชอบทำเวลาดีบั๊กคือ มาดูอันนี้ ดูเหมือนมันดึงมาแค่เก้ารายการ "วิดีโอและ media product คือ reel" เราอยากได้แค่ reels ใช่ไหม? ผมไม่สนใจ 30 วันที่ผ่านมา media product type เห็นไหมว่ามันเข้ามาเป็น items เราต้องการ reel insights จริง ๆ แต่เราได้แบบนั้น ถูกต้องแล้ว เรากำลังได้ media แล้ว push ลงไป เจ๋ง สมเหตุสมผลสำหรับผม โอเค

มันได้ media product ผิด และทั้งหมดนี้เข้ามาเป็น array เดียว เราจึงต้องแยกมันออกเป็นหลาย items สิ่งที่ผมจะทำคือเพิ่ม split out item แยกออกมา แยก data fields ดูว่ามันทำอะไรให้ผม 442 items นั่นคือ reels ทั้งหมดของผมตรงนั้น โอเค แล้วเราจะกรอง media product ที่เป็น reels มันควรกรองออกประมาณห้าโพสต์ เจ๋ง เยี่ยม ตอนนี้เรากำลังส่งแต่ละ reel เข้าไป ผมจะ pin อันนี้ มันอาจไม่ให้ pin ข้อมูลเยอะขนาดนี้ มันทำได้ เจ๋ง โอเค ตอนนี้เราจะลูปมัน แล้วส่งลงไปตรงนี้ นี่คือ access token ของผม แต่ผมซ่อนไว้เพื่อให้คุณเห็นแค่ครึ่งเดียว เจ๋ง

ดูเหมือนมันดึง reel insights ทั้งหมดแล้ว ได้ views ทั้งหมด ได้ Instagram total watch, reels watch total, shares, reach, money แล้วเราจะ set ออกมา ดูเหมือนมันจัดระเบียบทุกอย่างให้เรา บูม ดูว่ามันทำงานไหม "Unknown field Instagram media ID" มาดู "คำขอของคุณไม่ถูกต้องหรือไม่สามารถประมวลผลได้ Unknown field name Instagram Media ID" ดูเหมือนมันอาจเปลี่ยนชื่อมัน มาดู มันทำได้ดี ที่จริงมันน่าจะเวิร์กหลังจากนี้ "ฟิลด์ Instagram ID เราต้องเปลี่ยนเป็น single line text เพราะรู้ว่า JSON ยาว" โอเค เรามาตรงนี้ เรา matching คอลัมน์ด้วย media ID และนั่นควร... มาดู ไปเลย เอาล่ะ "คำขอของคุณไม่ถูกต้อง Unknown field name Instagram media ID" เพื่อน นายโกหก นายโกหก ผมกำลังดูอยู่ ไปดูแบบลิสต์ บางครั้งมันใส่ของผิดตรงนี้ เราอยู่ในเวิร์กโฟลว์ตัวอย่าง ตาราง ใช่ แล้วเราอยู่ข้างใน ดูสิ ผมคิดว่ามันเปลี่ยนชื่อแล้ว มันควรชื่อ imported table ขอดูหน่อย นั่นคือ Instagram ID ผมพลาดอะไรบางอย่าง โอเค

ดูว่ามันทำงานไหม มันยังให้ error อยู่ ดูนี่สิ อันนี้เจ๋ง นี่คือสิ่งที่ผมชอบทำ ผมชอบให้ trigger อีกตัวกับมัน โดย trigger นี้เป็น webhook สิ่งนี้ทำให้ Claude Code trigger เวิร์กโฟลว์ให้ผมได้ เพื่อที่มันจะดีบั๊กเอง ผมต้องทำ POST request ไปที่ production URL ผมจะลบอันนี้เพื่อให้คุณเห็น "CC workflow example" ผมจะเอา production อันนี้ ผมจะ publish อันนี้ ดูเหมือนมัน publish ไปแล้ว เราควรจะชัวร์ เจ๋ง "ผมให้ webhook trigger คุณไว้สำหรับทดสอบโฟลว์นี้เอง"
